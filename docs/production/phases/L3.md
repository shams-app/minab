# L3 — Names in any language, quoted names, physical names

| Lane | Kind | Size | Depends | Decisions | Release |
|---|---|---|---|---|---|
| L — Language | Design → Mechanical | M | [L2](L2.md), [C1](C1.md) | [D12](../decisions.md#d12) | 0.3.0 |

## Goal

Minab can name every table and field a Shamsine user can create: Persian, Arabic and Turkish letters, and names with spaces or symbols (in backticks). The compiled SQL uses each name's physical database name.

## Why now

Shamsine field names are free text (`z.string().min(1)`), and Dynodb uses them as Postgres column names. Without this, Shamsine users cannot reference most of their own fields. It is a grammar change, so it sits in the grammar chain after L2.

## Read

- `src/language/minab.langium`: `terminal ID`, and every place that uses `ID` (names after `.`, `#`, `FROM`, `AS`, `let`, `fn`, parameters, labels, JSON keys)
- Langium's value converter (`node_modules/langium/lib/parser/value-converter.d.ts`) and how a datatype rule returns a string
- `src/language/schema.ts`, `src/host/config.ts` (`parseSchema`)
- `src/language/minab-sql-compiler.ts`: `quoteIdent` and every place a table or column name becomes SQL; how `primaryKey` and `foreignKey` are used
- `playground/src/syntax/tokens.ts`, `playground/src/monaco/language.ts`
- `test/differential/README.md` and `test/support/` (from C1)
- Decision D12

## Ask first

None. D12 is the approved proposal. If Langium cannot take Unicode property escapes in a terminal (see Build 1), the explicit character ranges are an implementation detail, not a new decision.

## Build

1. **Plain names**: change `terminal ID` to accept any Unicode letter or `_` first, then letters, digits, `_`, and (not first) U+200C and U+200D. First try a Unicode property regex (`\p{L}`, `\p{N}` with the `u` flag). If Langium 4.4 or Chevrotain does not accept it, use explicit ranges that cover at least: Latin with Latin-1 Supplement and Extended-A/B (Turkish `İ ı ş ğ ç ö ü`), Greek, Cyrillic, Hebrew, Arabic, Arabic Supplement and Extended-A (Persian `پ چ ژ گ ی ک`), Arabic Presentation Forms, Devanagari, CJK Unified Ideographs, Hangul. Write which one you used in the grammar comment.
2. **Quoted names**: a terminal for backtick names (`` `…` `` with `` \` `` and `\\` escapes) and a datatype rule `Name returns string: ID | QUOTED_NAME;` used wherever a user-facing name is written today. A value converter removes the backticks and the escapes. Inside backticks a keyword is a plain name (`` .`FROM` ``). Run `npm run langium:generate`: no new warnings.
3. **Keywords stay ASCII** and case-sensitive. Check that no Unicode letter range makes a keyword ambiguous (they cannot: keywords are matched first by Langium's keyword rules; prove it with a test).
4. **Physical names**: `MinabTableSchema.sqlName?` and `MinabColumnSchema.sqlName?`. The compiler quotes `sqlName ?? name`. Keep today's meaning of `primaryKey` (a schema column name, mapped through its `sqlName`) and `foreignKey` (a physical column name, which may not be a schema column); write both meanings into `schema.ts`. `parseSchema` accepts `sqlName`.
5. **Result rows** keep Minab names as keys (`SELECT` aliases are Minab names).
6. **Positions**: diagnostics keep correct line and column with Persian text before the error (Langium uses UTF-16 offsets; the CLI caret must line up for characters in the Basic Multilingual Plane). Test it.
7. **Spec** (approved by D12): a "Names" subsection (in §2 or §7.1, wherever names are first defined) with the rules and the examples from D12; §11 grammar block. **Showcase**: a new numbered section with a Persian example and a backtick example.
8. **Highlighting**: `vscode-extension/syntaxes/minab.tmLanguage.json` is generated (check it highlights Unicode and backtick names as names); `playground/src/syntax/tokens.ts` and the Monaco language accept both kinds; `playground/test/tokens.test.ts` covers them.
9. **Playground**: one gallery example with Persian names (a small Persian dataset in `playground/src/content/datasets/`), useful for the TV demo (W5). Its test runs it.
10. **Differential cases**: `test/differential/cases/l3-names.cases.ts` with Unicode column names and `sqlName` (needs C1's PGlite helper).

## Files

`src/language/minab.langium`, a value converter in `src/language/` (new or in `minab-module.ts`), `src/language/schema.ts`, `src/host/config.ts`, `src/language/minab-sql-compiler.ts`, `src/language/minab-scope-resolver.ts` (if it compares raw names), tests (`test/names.test.ts` new, differential cases), spec, showcase, playground tokenizer, Monaco language, a gallery example and dataset.

## Do not touch

Field-type mapping for Shamsine (G2). Locale-specific case rules (none: names are case-sensitive and compared exactly).

## Output

Any name works. `sqlName` lets hosts keep Minab names and database names apart.

## Test scenarios

- `FROM سفارش WHERE .وضعیت == "ارسال‌شده" SELECT .مبلغ AS مبلغ_کل` parses, checks and runs on PGlite.
- `` .`Order date` <= .`Ship date` `` parses and checks; `` .`FROM` `` is a field named FROM.
- A backtick name with `` \` `` inside.
- `.İl == "İzmir"` works; `ılçe` works.
- U+200C inside a Persian name works; at the start it is a syntax error.
- `sqlName: "fld_ab12"` on column `نام` → the SQL uses `"fld_ab12"`; the row key is `نام`.
- A `sqlName` containing `"` is quoted safely (doubled) and the query runs.
- A type error after Persian text: the CLI caret sits under the right character.
- Every keyword is still a keyword; a Unicode name that looks like a keyword (`FROMا`) is a name.

## Done when

All of the above pass; `langium generate` shows no new warning; root, playground and extension green; spec and showcase updated.

## Not here

Field type mapping (G2). Unicode-aware `UPPER`/`LOWER` (L5).

## Later

None expected.

## If it grows

The playground gallery example may move to Later (lane W). Everything else is required.
