# R4 — Limits, cancellation and structured run errors

## Goal

A run can be cancelled, it stops at its limits, and every failure — at prepare, compile or run time — is a structured error with a stable code, a message, a source range and parameters. A host can map it to an HTTP status or an editor marker without parsing text.

## Why now

A server running user-written programs needs this before anything else (D01). The CLI, the playground and the hosts (R7, R8, H) consume these shapes.

## Build

1. **`src/runtime/limits.ts`**: the limits of D36 with their defaults; `createMinab({ limits })` sets defaults, `run(…, { limits })` may lower (never raise above the host's) them per run.
2. **Where each limit is checked**: source length and nesting at `prepare` (`limit.sourceTooLong`, `limit.tooDeep`); wall time at every interpreter step and around every port call (`limit.timeout`); statements per run before each data call (`limit.tooManyStatements`); rows per statement after each data call (`limit.tooManyRows`); function call depth on each user `fn` call (`limit.callDepth`); loop iterations through a counter X4 will call (`limit.tooManyIterations`); log entries (counted, not an error: L7).
3. **Cancellation**: `run(…, { signal })`. The interpreter checks the signal between steps; every port call gets the signal. An aborted run ends with `cancelled`.
4. **Structured results**: `run` returns `{ ok: true, value, logs, stats: { statements, rows, durationMs } }` or `{ ok: false, error: { code, message, range?, params } }`. `compile()` returns `{ ok: true, sql }` or `{ ok: false, error }`. Interpreter and compiler failures get codes in the registry (`eval.*`, `compile.*`) instead of free text; keep today's English messages.
5. **Data errors**: a data port failure becomes `data.error` with `params.sqlstate` when the error has one; Postgres's `22012` maps to `eval.divisionByZero`, `22P02` and `22003` to `eval.castFailed`, so both runtimes report the same code. SQL text is never put in the error message (hosts may log it from the event stream).
6. **Compatibility for old callers**: keep a small adapter that turns the new result into today's `EvalResult` until R7 and R8 move the CLI and the playground; mark it `@deprecated` and remove it in R8 (or in whichever of R7/R8 merges last; say so in your status file).
7. Docs: `src/runtime/README.md` (the result and error shapes, the limits table); `docs/reference/diagnostics.md` regenerates with the new codes.

## Test scenarios

- A host function that waits 2 s with a 100 ms wall-time limit → `limit.timeout` within about 150 ms.
- Aborting during a slow data call → `cancelled`, and the data port saw the abort.
- A recursive `fn` → `limit.callDepth` at depth 64.
- 101 statements with the default → `limit.tooManyStatements`; a data port that returns 10,001 rows → `limit.tooManyRows`.
- A 70 KB source → `limit.sourceTooLong` at `prepare`.
- `5 / 0` interpreted and a Postgres `22012` both → `eval.divisionByZero`.
- A failing `CAST` has `range` pointing at the `CAST`.
- `run` per-call limits cannot exceed the host's limits.
