# E1 — Editor services core

| Lane | Kind | Size | Depends | Decisions | Release |
|---|---|---|---|---|---|
| E — Editor | Mechanical | M | [R8](R8.md) | — | 0.3.0 |

## Goal

Completion, hover, go-to-definition and signature help are computed once, in `src/editor/`, with no environment (no Node, no DOM, no LSP types). The language server (E2), the Monaco integration (E5) and the playground all use the same code.

## Why now

The playground already implements these (`playground/src/engine/intel.ts`). Moving them into the library is mostly porting. After L1, a call's callee resolves to its `FunctionDecl`, so functions get hover and go-to-definition too.

## Read

- `playground/src/engine/intel.ts` (all of it), `playground/src/engine/protocol.ts` (the shapes it returns)
- `src/language/lsp/minab-hover-provider.ts`, `minab-definition-provider.ts`
- `src/language/minab-type-checker.ts` (`inferType`), `src/language/minab-scope-resolver.ts`
- `src/runtime/` README (how a prepared program keeps its document)
- `src/language/minab-builtins.ts` (L5's table, if merged: for signatures)

## Ask first

None.

## Build

1. **`src/editor/`** (with a README), pure functions over a prepared program or a parsed document plus an offset:
   - `complete(doc, offset)`: columns after `.` (of the right table, following relations), tables after `FROM` and `#`, aliases, `let` names and parameters in scope, built-ins (with signatures), user `fn` names, host functions and inputs (R3), keywords allowed at that position. Each item: label, kind, detail (type or signature), documentation (from the diagnostics registry style: one sentence), insert text;
   - `hover(doc, offset)`: a column's type (and `sqlName` if different), a function's signature and doc, a `#alias`'s table, any expression's inferred type;
   - `definition(doc, offset)`: `#alias`, `let`, parameter, `fn` → the declaring range;
   - `signatureHelp(doc, offset)`: for built-ins, user functions and host functions, with the active parameter.
   - Ranges are line/column (0-based) and offsets; no LSP or Monaco types (adapters convert).
2. The playground's `intel.ts` calls `src/editor/` and only converts results to its protocol shapes. Its behavior stays the same.
3. The existing LSP hover and definition providers call `src/editor/` (E2 adds completion and the rest).
4. Table-driven tests (`test/editor/*.test.ts`) with cursor markers in the source (`.cus|tomer`), for every item kind.

## Files

`src/editor/*` (new), `playground/src/engine/intel.ts`, `src/language/lsp/minab-hover-provider.ts`, `src/language/lsp/minab-definition-provider.ts`, `test/editor/*` (new).

## Do not touch

`src/language/main.ts` and the server's capabilities (E2). Monaco wiring (E5).

## Output

One editor-intelligence library for every editor host.

## Test scenarios

- `.` after `FROM Order WHERE ` lists `Order`'s columns; `.customer.` lists `Customer`'s.
- After `FROM ` lists tables; after `#` lists tables.
- Inside `discounted(` signature help shows the parameters, with the active one.
- Hover on `discounted` shows its signature; F12 jumps to its `fn`.
- Hover on a Persian column name works (if L3 is merged).
- A host input appears in completion with its type.

## Done when

`src/editor/` is tested; the playground and the LSP use it with no behavior change (their tests are green).

## Not here

New LSP features and per-document schemas (E2, E3). Monaco (E5).

## Later

None expected.

## If it grows

Signature help may move to E2 (it is mostly wiring there).
