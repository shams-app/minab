## Goal

The VS Code extension is something you would publish: snippets, an icon, settings, a status-bar item that names the loaded config, a restart command, a good README, an automated smoke test, and a short guide for using the language server in other editors.

## Why now

The server is complete enough to be worth installing (E2). The release workflow (Q2) publishes the extension.

## Read

- `vscode-extension/` (all: `package.json`, `src/extension.ts`, `README.md`, `.vscodeignore`, `language-configuration.json`)
- `src/lsp/` README (E2: configuration the server accepts)
- `docs/releasing.md` (Q2)
- Decisions D04, D09

## Ask first

The icon: do you have one (the website's brand, W1), or should the session make a simple one from the wordmark (`.minab`, the dot in the record-sigil color)? Recommended: use W1's mark if it exists; otherwise a simple temporary icon, replaced later.

## Build

1. **Snippets** (`snippets/minab.json`): record rule, field rule, query (`FROM … WHERE … SELECT`), `fn`, `switch`, `if`, a loop form.
2. **Settings**: `minab.configPath` (override discovery), `minab.trace.server` (`off`/`messages`/`verbose`). The server reads `configPath` (small change in `src/lsp/`; tell the owner if E3 is running at the same time).
3. **Status bar**: shows the config file used by the active document ("Minab: examples/top-customers/minab.config.json" or "Minab: no config"); click opens it. Needs a small custom notification or request from the server; add it to `src/lsp/`.
4. **Command** `Minab: Restart Language Server`.
5. **Marketplace listing**: icon (128×128 PNG), `galleryBanner`, `categories`, `keywords`, `repository`, `bugs`, `homepage`; README with features, settings, a screenshot or GIF (the owner can record one; leave a placeholder path and say so).
6. **Smoke test** with `@vscode/test-electron` (D09): opens an example folder, waits for activation, asserts a diagnostic appears on a file with a type error. New workflow `extension-test.yml` (Linux with `xvfb-run`).
7. **Other editors**: `docs/editors.md` with exact launch lines for Neovim (`nvim-lspconfig`), Helix (`languages.toml`) and Zed. The server starts with `node <path to the package>/out/src/language/main.js --stdio`. If a `minab-lsp` command makes those lines simpler, add it as a second `bin` entry in the root `package.json` (one line; mention it in your changelog fragment). Run each line once and write how in your status file.
8. Update Q1's `.vsix` content guard for the new files (icon, snippets).

## Files

`vscode-extension/**`, `src/lsp/*` (settings, status notification), `docs/editors.md` (new), `.github/workflows/extension-test.yml` (new), root `package.json` (`bin`, only if Build 7 needs it).

## Do not touch

The release workflow (Q2: it already publishes the `.vsix`).

## Output

An extension ready for the Marketplace and Open VSX.

## Test scenarios

- The `.vsix` guard passes with the new files.
- Each launch line in `docs/editors.md` was run once (write how in your status file).
