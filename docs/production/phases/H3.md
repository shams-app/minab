## Goal

`examples/nestjs/` is a small NestJS app, set up the way `nest new` sets one up (CommonJS, TypeORM, Postgres), that validates records with a stored correlated rule inside a request transaction, runs a stored query, and serves the run endpoint the browser example (H6) calls. Its end-to-end tests run in CI against Postgres.

## Why now

It proves the Node and NestJS pieces together, as a user installs them, and gives the browser example a server.

## Build

1. `examples/nestjs/`, its own npm package (like `playground/`): NestJS 11, TypeORM with `pg`, Jest + supertest. It depends on Minab through the **packed tarball** (`npm pack` in the root, then install it), so it tests what users get. A script `npm run setup` does this.
2. **Program store**: programs live in a table `minab_program (id, version, source, language_version)` seeded by a migration; the app's `ProgramStore` reads it.
3. **Endpoints**:
   - `POST /orders/validate`: in a TypeORM transaction (`QueryRunner`), insert the incoming order, run the stored rule `order-limit` v1 (a correlated rule: "a customer may have at most 5 open orders") with a data port bound to the transaction, commit on `true`, roll back and answer 422 with the rule id on `false`;
   - `GET /reports/top-customers`: runs a stored query program;
   - `POST /minab/run`: the H2 controller (stored programs only).
4. `examples/nestjs/README.md`: a walkthrough that G1's guide will cite (install, schema loader, program store, transaction, endpoints, security note: the schema is the read surface).
5. **End-to-end tests**: the three endpoints, the rollback path, a refused source-text run, a 422 with codes for a broken stored program, logs off in production mode.
6. New workflow `example-nestjs.yml`: Postgres service, root build and pack, install, migrate, e2e tests.
7. Exclude `examples/nestjs/**` from the npm package (`files`) — the example is for the repository, not the package. (This is a one-line `files` change; `files` is not a protected field.)
