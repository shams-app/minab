## Goal

`createMinab` / `prepare` / `PreparedProgram` exist in `src/runtime/`, free of any environment (no Node, no DOM, no `pg`), with a cache of language services, one document per `prepare`, proof that concurrent runs are independent, and the package's full `exports` map ready for the later entry points.

## Why now

Everything after it (ports, hosts, editors) builds on this API. ADR 0002 (R1) defines it; L1 settled how calls look.

## Build

1. **`src/runtime/`** (with a README):
   - `index.ts`: the public exports;
   - `minab.ts`: `createMinab({ schema, ruleContext?, limits?, mode? })` returns a `Minab` with `prepare`, `dispose`. `mode` defaults to `'production'` parser mode (fast) except in tests;
   - `prepare.ts`: `prepare(source, { ruleContext?, expect? })` returns a `PreparedProgram`: `diagnostics` (with codes, severity, range, params), `ok`, `kind` (query, record rule, field rule, value, empty: reuse `playground/src/engine/program.ts`'s logic, moved here), `resultType`, `compile()` (SQL or a coded refusal), `run(inputs, ports, options)`.
   - For now `run` takes today's executor and record (`{ record, fieldValue }`, `{ data: executor }`) and calls the interpreter; R3 replaces this with the full ports.
   - `expect`: when given (a Minab type), a result type that does not fit gives `type.unexpectedResultType` (Shamsine's `expect: 'boolean'` etc.).
2. **Service cache**: language services per schema `version` (or a hash of the schema when `version` is missing), LRU with a size cap (default 16), `dispose()` frees them.
3. **Document lifecycle**: each `prepare` uses its own document URI (`minab:///prepared/<n>.minab`) and removes the document from the shared workspace when done, so a long-running server does not grow. The prepared program keeps what it needs (the AST, the types) and no reference to the workspace.
4. **Concurrency**: a test runs 50 `prepare` + `run` pairs at once on one `Minab` (different sources, records and fake data ports) and checks every result. If they interfere, apply the solution the ADR chose (a pool, or documents outside the workspace).
5. **Environment guard**: `test/runtime-imports.test.ts` walks the import graph from `src/runtime/index.ts` and fails on `node:*`, `langium/node`, `vscode-languageserver/node`, `pg`, or the use of `window`/`document`.
6. **Package entry points** (D31, the full map now, so later phases never edit it):
   - `exports` for `.` (the runtime), `./node`, `./nestjs`, `./browser`, `./browser/worker`, `./browser/pglite`, `./monaco`, `./lsp`, `./host`, each with `types` and `import`, plus `./package.json`;
   - entry files that do not exist yet are small stubs in their folders (`src/node/index.ts`, `src/nestjs/index.ts`, `src/browser/index.ts`, `src/browser/worker.ts`, `src/browser/pglite.ts`, `src/monaco/index.ts`) that export a `notReady` constant and a comment naming the phase that fills it. `./lsp` exports a function that starts today's server; `./host` exports `parseConfig` and the fixture executor;
   - `typesVersions` mapping the same subpaths, so TypeScript projects with old `moduleResolution: node` (common in NestJS) find the types;
   - `peerDependencies` and `peerDependenciesMeta` (all optional): `pg`, `@nestjs/common`, `@nestjs/core`, `rxjs`, `reflect-metadata`, `@electric-sql/pglite`, `monaco-editor`;
   - extend `test/release.test.ts`: every `exports` target exists in the packed tarball.
   - CommonJS `require` targets are added by H1, not here.
7. **Parity test**: every example in `examples/` prepared and run through the runtime API gives the same answer as its `expected.json`.

## Files

`src/runtime/*` (new), `playground/src/engine/program.ts` (re-export what moved, if anything moved), stub entry files (new), `package.json` (`exports`, `typesVersions`, peers), `test/runtime.test.ts`, `test/runtime-concurrency.test.ts`, `test/runtime-imports.test.ts` (new), `test/release.test.ts`.

## Output

The runtime API core and the package's final entry-point map.

## Test scenarios

- `prepare` of a valid rule: `ok`, `kind: 'record-rule'`, `resultType` BOOLEAN; of a broken one: coded diagnostics with ranges.
- `expect: BOOLEAN` on `.total + 1` → `type.unexpectedResultType`.
- The same schema version twice → the cache is hit (count service creations); 17 schemas with cap 16 → the oldest is dropped.
- After 1,000 `prepare` calls, the shared workspace holds no prepared documents.
- 50 concurrent runs are all correct.
- The import guard fails if you add `import 'node:fs'` to a runtime file (try, undo).
- Every example gives its expected answer through the API.

## Done when

All of the above pass; `npm pack --dry-run` contains every export target; root and playground green.

## Not here

Ports beyond today's executor (R3), limits (R4), analysis (R5), wire format (R6), moving the CLI and the playground (R7, R8).

## Later

None expected.

## If it grows

The `./lsp` and `./host` entries may stay minimal re-exports. The parity test and the concurrency test must stay.
