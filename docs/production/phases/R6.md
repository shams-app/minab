## Goal

A versioned JSON format for "run these programs with these inputs" and its answer, with exact value encoding, so the browser client (H5) and the NestJS endpoint (H2) can be built at the same time against one contract.

## Why now

H2 and H4/H5 both need it; with it fixed, they run in parallel.

## Build

1. `src/runtime/wire.ts` (+ `docs/reference/wire-format.md`):
   - **request**: `{ "v": 1, "runs": [ { "id", "program": { "ref": { "id", "version" } } | { "source" }, "inputs"?, "record"?, "fieldValue"?, "options"?: { "limits"?, "logs"? } } ] }`. `source` is accepted only by servers in development mode (D34);
   - **response**: `{ "v": 1, "results": [ { "id", "ok": true, "value", "logs"?, "stats" } | { "id", "ok": false, "error": { "code", "message", "range"?, "params" } } ] }`;
   - **value encoding by Minab type**: `DECIMAL` as a string, `INTEGER` as a number, `BOOLEAN`, `TEXT`/`CITEXT`/`UUID` as strings, `DATE`/`TIME`/`DATETIME` as ISO 8601 strings, `JSON` as is, arrays and records element by element, `null` as `null`. `encodeValue(value, type)` and `decodeValue(json, type)` round-trip exactly;
   - **validation**: `parseRequest(json)` and `parseResponse(json)` check the shape (hand-written checks, no new dependency) and return coded errors: `wire.unsupportedVersion` (unknown `v`), `wire.invalidRequest`, `wire.tooManyRuns` (D36: 100).
2. A JSON Schema file for each shape (`schemas/wire-v1.request.json`, `schemas/wire-v1.response.json`) for non-TypeScript clients, checked against the TypeScript types by a test.
3. Tests: round-trip every type; reject a request with `v: 2`, a missing `id`, 101 runs; a decimal survives `JSON.stringify`/`parse` exactly.
