# E5 — Monaco integration for host apps

| Lane | Kind | Size | Depends | Decisions | Release |
|---|---|---|---|---|---|
| E — Editor | Mechanical | M | [E1](E1.md), [H4](H4.md), [L7](L7.md) | [D09](../decisions.md#d09) | 0.3.0 |

## Goal

A web app that uses Monaco (Shamsine's expression editor, cards M.12 and M.13) gets Minab support with one call: `registerMinab(monaco, { client })` adds the language, highlighting, brackets and comments, error markers, completion, hover and signature help, all computed in the browser worker.

## Why now

Shamsine's editor needs it at 0.3.0. E1 has the computations; H4 has the worker and its bridge. The browser example (H6) shows it. It waits for L7 because it moves the playground tokenizer, which the grammar phases (L1, L3, L4, L7) edit: after this phase they edit `src/editor/tokens.ts` instead.

## Read

- `playground/src/monaco/language.ts`, `playground/src/syntax/tokens.ts` (the playground's Monaco language and the one tokenizer it shares with static snippets)
- `src/editor/` README (E1), `src/browser/` README (H4)
- `playground/test/tokens.test.ts` (it fails if the grammar gains a keyword the highlighter does not know)
- Decision D09 (`monaco-editor` as an optional peer)

## Ask first

None.

## Build

1. **Move the tokenizer** from `playground/src/syntax/tokens.ts` to `src/editor/tokens.ts` (pure; the playground re-exports it, its tests keep passing). The keyword list comes from the grammar's keywords (as the playground test already checks).
2. **`src/monaco/`** (entry `./monaco`, replacing R2's stub; README):
   - `registerMinab(monaco, { client, languageId? })`: registers the language id `minab`, a Monarch tokens provider built from the tokenizer's rules, the language configuration (brackets, auto-closing quotes and backticks, `//` and `/* */` comments);
   - a diagnostics loop: on content change (debounced, about 150 ms), `client.prepare` in the worker → Monaco markers (code shown in the marker, message, range);
   - completion, hover and signature-help providers that call new worker methods (`complete`, `hover`, `signatureHelp`) the worker answers with `src/editor/` (add those methods to H4's protocol; it is versioned);
   - types only from `monaco-editor` (optional peer); no runtime import of Monaco by Minab.
3. **RTL note** in the README: Monaco shows code left to right; Persian and Arabic names inside code display correctly within a left-to-right line; put the editor in an element with `dir="ltr"` inside right-to-left pages (Shamsine).
4. Tests: the Monarch rules on sample lines (keywords, sigils, strings, backtick names, Unicode names, comments); the providers with a fake `monaco` object and a fake client (Node).
