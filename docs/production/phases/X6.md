## Goal

The other half of writes: `INSERT`/`UPDATE`/`DELETE` on `JSON` arrays (read, change in memory, write back), including position-based forms, and assignment through a record path (`.doctor.id = 21;`), with `!` creating missing related records and `|=` merging. All eleven examples run.

## Why now

It needs table writes (X5) and `.$index` (X4). After it, every construct the grammar accepts runs.

## Build

1. **`JSON`-array targets** (ADR 0001): read the value, apply `INSERT`/`UPDATE`/`DELETE` in memory, write the new value back with one `UPDATE` of that column through the write port. Position forms: `DELETE .customers[2]`, `… WHERE .$index > 2`.
2. **Path assignment through a record** (§9.3): `.doctor.id = 21;` (no-op when `.doctor` is `null`), `.doctor!.id = 21;` (create the missing related record first: an `INSERT` of a new row with defaults, then link it), `.a!.b.c!.d.e! = …` mixed paths, `|=` merge into a `ref` (update those fields, creating the record if missing), filtered collection paths (`.doctor.patients[.city == "istanbul"].activate = true;` → one `UPDATE … WHERE`).
3. A `!` step that cannot be created (a required column has no value) → `eval.cannotCreateRecord` naming the table and column. `!` on a collection step is already a check error (L4).
4. All writes use X5's transaction and write modes (dry run lists the statements, including the read-back-and-write of `JSON` arrays).
5. **Examples**: `order-dml` and `reconcile-overdue-accounts` become runnable (`expected.json` with dry-run output); all eleven examples now run. Update the examples test where it asserted refusals. README output blocks only if a checked one changes.
6. **Playground**: no construct left in the check-only list; cheat sheet; gallery examples for writes run in dry-run mode (the playground shows the statements; its PGlite may also apply them, since the database is local and resettable — follow how the playground resets data today).
7. Tests on Postgres: `JSON` array changes persist; vivify creates and links a row; a failing vivify rolls back the whole run; filtered path assignment updates only matching rows.
