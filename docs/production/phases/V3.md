## Goal

Minab 0.4.0 is released. It brings the `null` and `IN` rules (C9), literals and kind tests that Postgres accepts (C10), and the host safety fixes (H8). It is the first release made only by the release workflow, from a tag push (Q6). The extension gets the same version, and the owner checks it from the Marketplace.

## Why now

This card changed on 2026-10-11. Its old theme, "the whole language runs" (statements, loops, writes, `LOG`, the full language server), already shipped in 0.2.0, because V1 ran after lanes X and E had merged. 0.3.0 then added E4 and Q5. On 2026-10-06 a V3 session found nothing to release and stopped. Its status file never reached `main`.

Now 0.4.0 carries the fixes that V4 (the 1.0 gate) needs. It is also the second release made only by the workflow, which V4 point 8 needs (0.3.0 is the first; 0.2.0 needed manual steps).

## Build

1. **Check** that every Depends is done and every workflow is green on `main`.
2. **Release PR** `[V3] Release 0.4.0` on the branch `release/v0.4.0`:
   - `scripts/bump-version.mjs 0.4.0`;
   - `scripts/changelog.mjs --version 0.4.0` (the fragments of C9, C10, H8, W5, W6 and any other phase merged since 0.3.0);
   - `README.md` and the CHANGELOG: the status line, and the known limitations with the same text in both files (remove what C9, C10 and H8 fixed; check each item against `main`);
   - `npm run compat:snapshot 0.4.0`.
3. **Release by machine only.**
   - After the owner merges the PR, run **Release** on `main` with `dry-run` on (the default) and see it pass.
   - Push the tag `v0.4.0` only if the owner said so. Otherwise give the owner the exact command (`git tag v0.4.0 && git push origin v0.4.0`). The tag starts `release.yml`.
   - No manual step. If a step fails or is skipped (for example an expired `VSCE_PAT`), fix the cause and run **Release** again on the tag (Q6 allows it). Do not publish or create the GitHub release by hand.
   - Write every step and every run link in the status file. V4 point 8 reads it.
4. **Verify from npm**, as in V2:
   - the consumer projects (H1) against the published tarball;
   - both examples with the published 0.4.0;
   - `minab --version`, `check` and `run` in a clean folder;
   - the GitHub release has the notes and the `.vsix`.
5. **Manual check (the owner).**
   - Install the extension from the Marketplace or Open VSX.
   - See: completion after `.`, hover, rename, a quick fix, two folders with different configs, the squiggle, the status bar item, the snippets, `minab.configPath` and the restart command.
   - Check that the extension's `homepage` link opens the live website.
   - The owner tells the session the result. Record it.
