# V4 — Production readiness review

| Lane | Kind | Size | Depends | Decisions | Release |
|---|---|---|---|---|---|
| V — Releases | Mixed | M | [V3](V3.md), [W4](W4.md) | [D02](../decisions.md#d02), [D38](../decisions.md#d38), [D39](../decisions.md#d39) | 1.0.0 |

## Goal

A written, evidence-backed check that Minab meets every point of "What production level means" (`docs/production/README.md`). Small gaps are fixed here; larger ones go to the owner. The result is `docs/production/readiness.md`.

## Why now

0.4.0 has the complete language, and the website is live. This is the gate to 1.0.

## Read

- `docs/production/README.md` ("What production level means"), `docs/production/progress.md` (every status, every Later item, every open question)
- `docs/query-language-spec.md` §12, `docs/adr/0001-execution-strategy.md` (consequences)
- `docs/security.md`, `docs/performance.md`, `docs/compatibility.md`, `docs/guides/*`, `docs/reference/*`
- The latest CI runs of every workflow
- Decisions D02, D38, D39

## Ask first

None at the start. At the end, the owner approves the review.

## Build

1. **`docs/production/readiness.md`**: one section per point of "What production level means", each with a verdict (met / not met) and **evidence** (a test file, a workflow run link, a document). Checks:
   1. **Correct**: no `knownGap` left in the differential cases; the query harness and the Postgres workflow green; no open bug in any status file's Later list.
   2. **Complete**: search the source for "not executed yet" and other refusal messages: none left except deliberate, documented ones (statements inside a query, functions that cannot be inlined). Every grammar construct has a showcase example that runs or is a documented check error.
   3. **Embeddable**: the consumer workflow and both example apps green against the published 0.4.0.
   4. **Safe**: Q3's suites green; CodeQL (if enabled) and `npm audit` clean; `SECURITY.md` present; ask the owner whether to get an outside security review (Q3's Later).
   5. **Fast enough**: Q4's budgets met on the latest run.
   6. **Ready for Shamsine**: G2's guide complete; ask the owner whether Shamsine's integration (in the monorepo) found any Minab problem.
   7. **Stable**: the compatibility policy (D38) published; the corpus test green for 0.2.0, 0.3.0 and 0.4.0; every diagnostic code documented.
   8. **Released by machine**: the last two releases went through `release.yml` without manual steps.
   9. **Documented**: G1's link checker green; TypeDoc without warnings; the README matches reality.
   10. **Visible**: W4 signed off.
2. **The dialect decision** (D39): write "Postgres only for 1.x" into ADR 0001's consequences and the README (or, if D39 chose a second dialect, check it is tested).
3. **Spec §12**: only "resolved", "retired" or "post-1.0" items.
4. **License check**: list every production dependency and its license (`npm ls --omit=dev` plus each package's `license` field); all must allow MIT distribution. Write the list.
5. **Support**: `.github/ISSUE_TEMPLATE/` (bug report with a Minab program, schema and expected vs. actual; feature request), and a short "Support" section in the README (where to ask, what versions get fixes).
6. **Later triage**: every Later item from every status file is either done, moved to the post-1.0 list in `docs/production/phases/README.md` (ask the owner: that file is protected), or a blocker for 1.0 (then the owner decides the fix).
7. Fix small gaps (within the size budget) with tests; list the rest under "Questions for the owner" with a recommendation.
8. Status **`waiting for approval`** until the owner approves `readiness.md`.

## Files

`docs/production/readiness.md` (new), `docs/adr/0001-execution-strategy.md` (consequences), `README.md` (dialect, support), `.github/ISSUE_TEMPLATE/*` (new), small fixes as needed.

## Do not touch

The version number (V5).

## Output

An honest go/no-go for 1.0.

## Test scenarios

Every "met" verdict links to evidence that exists.

## Done when

`readiness.md` shows every point met (or the owner accepted an exception in writing), and the owner approved it.

## Not here

The release itself (V5).

## Later

Whatever the triage moves to post-1.0.

## If it grows

Fixes beyond the budget go to the owner as questions; the review itself must be complete.
