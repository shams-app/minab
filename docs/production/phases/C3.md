# C3 — `CAST` runs in the interpreter

| Lane | Kind | Size | Depends | Decisions | Release |
|---|---|---|---|---|---|
| C — Correctness | Design → Mechanical | M | [C2](C2.md) | [D16](../decisions.md#d16) | 0.2.0 |

## Goal

`CAST` converts values in the interpreter exactly as the compiled SQL does, for every target type, and a value that cannot convert fails with a clear, coded error. The spec says exactly what each cast does.

## Why now

Today the interpreter returns the operand unchanged: `CAST(3.7 AS INTEGER)` gives `3.7`, `CAST("12" AS INTEGER) + 1` gives `"121"`. Those are wrong answers. It needs C2's exact decimals.

## Ask first

None (D16 is the approved proposal).

## Build

1. A cast function per target type (`TEXT`, `CITEXT`, `INTEGER`, `DECIMAL`, `BOOLEAN`, `DATE`, `TIME`, `DATETIME`, `UUID`, `JSON`), following D16 and matching Postgres:
   - `DECIMAL` → `INTEGER`: round half away from zero; then the integer range check (C2);
   - text → number: trim spaces, then parse strictly (`"12a"` fails);
   - `DECIMAL` → text: shortest exact form; the compiler emits `trim_scale(x)::text` so SQL agrees;
   - text → `BOOLEAN`: Postgres's words, any case;
   - text → `UUID`: the canonical 8-4-4-4-12 hex form (any case), else fail;
   - text → `DATE`/`TIME`/`DATETIME`: ISO 8601 only;
   - `CAST(null AS T)` is `null`;
   - a cast the type checker allows but no rule covers (for example `JSON` → `INTEGER` of an object) fails with `eval.castFailed`.
2. Failure: an evaluation error with code `eval.castFailed` and params `{ value, from, to }` (registry entry). In SQL, the matching Postgres errors (invalid text representation, `22P02`; numeric out of range, `22003`) count as the same failure in the differential harness.
3. **Spec §5.5** (approved by D16): replace "truncates or rounds" with the exact rules, as a short table (from → to → what happens).
4. **Cases**: remove `knownGap: 'C3'`; add `test/differential/cases/c3-cast.cases.ts` with every supported pair, `null`, spaces, invalid strings, half values, negative values.

## Files

`src/language/minab-interpreter.ts` (or a new `src/language/casts.ts` it calls), `src/language/minab-sql-compiler.ts` (`trim_scale`), `src/language/diagnostics/codes.ts`, differential cases, spec §5.5, examples or README output blocks only if their output changes.

## Do not touch

`CITEXT` comparison rules (C5). Division (C4).

## Output

Casts that agree in both runtimes.

## Test scenarios

- `CAST(3.5 AS INTEGER)` = 4, `CAST(-3.5 AS INTEGER)` = -4, `CAST(3.7 AS INTEGER)` = 4.
- `CAST(" 12 " AS INTEGER) + 1` = 13; `CAST("12a" AS INTEGER)` → `eval.castFailed` in both runtimes.
- `CAST(5 AS TEXT) == "5"` is `true`; `CAST(2.50 AS TEXT)` = `"2.5"`.
- `CAST("Yes" AS BOOLEAN)` = `true`; `CAST("maybe" AS BOOLEAN)` fails.
- `CAST("not-a-uuid" AS UUID)` fails.
- `CAST(null AS DATE)` is `null`.

## Done when

No `knownGap: 'C3'` remains; all cast cases agree in both runtimes; spec §5.5 states the rules.

## Not here

`CITEXT` (C5). New types.

## Later

None expected.

## If it grows

It should not. `JSON` casts beyond "JSON text ↔ JSON" may move to Later if they need a design answer (ask the owner).
