# R3 — Ports: data, host functions and inputs, clock, events, write

## Goal

Everything a program needs from outside goes through a typed port: the data port (today's executor), host functions and host inputs (Shamsine's `currentUser`, `url`), a clock (for `NOW()`), one event stream (statements, logs, timing), and the write port's interface.

## Why now

L6 needs the clock, L7 the event stream, R4 passes cancellation through the ports, hosts (H) implement them.

## Build

1. **`src/runtime/ports.ts`**: the interfaces from the ADR: `DataPort`, `WritePort` (interface only), `HostFunctions` (implementation side), `ClockPort`, `EventSink`.
2. **Declarations at `createMinab`**: `functions: [{ name, params, returns, local?: boolean }]` and `inputs: { [name]: MinabType }` (scalars, arrays and records of typed fields, D27). They become part of the language services (the checker needs them), so they are part of the service cache key.
3. **Checker**: a bare name resolves to a `let`, a parameter, or a **host input** (read-only: assigning to it is `scope.assignToInput`). A call resolves to a built-in, a user `fn`, or a **host function**. D10's case rule applies to host function names (checked at `createMinab`: a clear error for the host developer). D11: a user `fn`, `let` or parameter may not reuse a host input or host function name (`scope.nameIsHostName`).
4. **Interpreter**: host inputs come from `run(inputs)`; a missing input value is the run error `eval.missingInput`. Host function calls go to the host implementation (awaited, with the `AbortSignal` R4 adds). The **compiler refuses** a host function call (`compile.hostFunctionInSql`), so it is never pushed into SQL; the interpreter takes that part.
5. **Clock**: `ClockPort` with `now(): Date` and `timeZone: string` (IANA). Default: the system clock and `UTC`. The run reads `now()` once (L6 uses it).
6. **Events** (D33): one `EventSink.emit(event)` with `{ kind: 'statement', sql, params, range, durationMs }`, `{ kind: 'log', … }` (reserved for L7), `{ kind: 'timing', phase, durationMs }`. Today's `onStatement` becomes the `statement` event, emitted just before the data port call (keep that order: the playground's execution map relies on it).
7. **Data port**: `DataPort.execute(query, { signal })` replaces `QueryExecutor` in the runtime API (keep `QueryExecutor` as a type alias for compatibility until R7/R8 move the hosts).
8. **Write port**: interface only, and a default that refuses with `eval.writesNotSupported`.
9. Remove the unused `MinabFunctionSchema` from `schema.ts` and `MinabSchema.functions` (pre-1.0; host functions replace it). Update `src/host/config.ts` and its tests; a config with `functions` gets a clear error that points to the new option.
10. Spec: a short §8 subsection "Host functions and host inputs" (approved by D27), and the showcase example from D27.

## Test scenarios

- `currentUser.id == .owner_id` checks with `currentUser: { id: TEXT }` declared, and runs with the input given.
- A run without the input → `eval.missingInput`.
- `fxRate("EUR", .currency)`: checks, runs through a fake implementation, and `compile` of a query using it refuses with `compile.hostFunctionInSql`.
- A host function named `RATE` → error at `createMinab`.
- `let currentUser: TEXT = "x";` → `scope.nameIsHostName`.
- Events arrive in order: statement events before each data call, with the source range.
- A fixed clock gives the same `now()` to every read in a run.

## Done when

All ports exist and are used; the tests pass; the spec describes host names; root and playground green.

## Not here

Limits, `AbortSignal` checks, structured run errors (R4). Date built-ins (L6). `LOG` (L7). Write execution (X5).
