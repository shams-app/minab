## Goal

Minab 0.3.0 is released: the runtime API, the Node, NestJS, browser and Monaco entry points, Unicode names, the built-in library with dates, the guides, and the security, performance and compatibility guards. Shamsine can depend on it. Per D02, this is the version Shamsine launches on.

## Why now

Everything Shamsine needs is merged and checked.

## Read

- `docs/releasing.md`, `CHANGELOG.md`, `changes/*.md`, `README.md`
- `docs/guides/shamsine.md` (G2: the monorepo follow-ups)
- `test/compat/README.md` (Q5: the corpus snapshot)
- Decision D02

## Ask first

- "Is `main` the state you want to release as 0.3.0?" (Show merged phases.)
- "May I push the tag from this session?"

## Build

1. Check: Depends done; every workflow green on `main` (including consumers, examples, browser bundle, perf, security).
2. Release PR `[V2] Release 0.3.0` on `release/v0.3.0`: `scripts/bump-version.mjs 0.3.0`; `scripts/changelog.mjs --version 0.3.0`; README status and limitations (same text in both files); `npm run compat:snapshot 0.3.0` (Q5) adds the corpus folder.
3. Tag and release as in V1 (owner's permission).
4. **Verify from npm**: run the consumer projects (H1) against the **published** 0.3.0 (ESM, CommonJS, Jest, Bun, old `moduleResolution`), plus the two examples with the published version instead of the tarball. Record results.
5. Give the owner G2's "Monorepo follow-ups" list as the closing message (they apply it in Shamsine).
