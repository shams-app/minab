## Goal

Every other page matches the approved design: the landing page (with its live demo), the tour (`/learn`), the example gallery, the reference (cheat sheet), the embed view, the 404 and error pages, and the mobile layout.

## Why now

W2 built the tokens and shared components these pages use.

## Read

- `playground/design/handoff.md`, the handoff bundle
- `playground/design/contract.md`, prompt 15
- `playground/src/ui/{landing,tour,gallery,reference,embed}/**`, `playground/src/routes/**` (only to see which components each page uses)

## Ask first

None.

## Build

1. Landing (hero demo with its loading states; Monaco and PGlite still load lazily, never on first paint), tour, gallery (filters, empty state), reference (search, drawer), embed (`?tabs=`, `?theme=`, `?readonly=`), 404 and route errors.
2. Mobile: below 760 px of workbench width the workbench becomes tabs (Code · Result · Host), as the brief says; every page works at 375 px.
3. Social image and icons (prompt 12): `public/` assets and meta tags in `index.html`.
4. Screenshots of each page at 1440 px and 375 px, light and dark, attached to the PR.

## Files

`playground/src/ui/{landing,tour,gallery,reference,embed}/**`, `playground/src/routes/*` (only layout wrappers, if the contract allows), `playground/public/*`, `playground/index.html` (meta tags).

## Do not touch

Engine, state, hooks, content.

## Output

The whole designed site, ready to deploy.

## Test scenarios

- Playground tests and build pass unchanged.
- The landing page's first paint loads neither Monaco nor PGlite (check the network panel or the build's chunk graph; write how in your status file).

## Done when

Every page matches `handoff.md` in both themes and both widths; tests and build green.

## Not here

Deploy and the Lighthouse pass (W4).

## Later

None expected.

## If it grows

The embed view's styling may move to W4. The landing page, tour and gallery must stay.
