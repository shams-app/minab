# C4 — Text `+`, division and `%`

| Lane | Kind | Size | Depends | Decisions | Release |
|---|---|---|---|---|---|
| C — Correctness | Design → Mechanical | M | [C2](C2.md) | [D13](../decisions.md#d13), [D14](../decisions.md#d14) | 0.2.0 |

## Goal

Text `+` works in both runtimes (or is rejected, per D13). Division and `%` give the same answers in both runtimes, including division by zero. The spec says what each operator does.

## Why now

Today `"a" + "b"` passes `check` but cannot run anywhere, `7 / 2` is `3.5` in the interpreter and `3` in Postgres for integer columns, and `5 % 0` is `null` in one and an error in the other. These are wrong answers.

## Ask first

None (D13, D14 are the approved proposals).

## Build

1. **Text `+`** (D13 option a): the checker allows `+` when both sides are text (`TEXT`/`CITEXT`), result `TEXT` (nullable if either side is); text with a number is a type error naming `CAST`. The interpreter joins the texts (`null` side → `null`). The compiler emits `||`. (If D13 is option b: the checker rejects text `+` with a message that names the alternative, and no runtime change.)
2. **Division** (D14): `/` gives a `DECIMAL` with 16 digits after the point, rounded half away from zero, in both runtimes.
   - Interpreter: `big.js` division with 16 decimal places and the half-away-from-zero mode, then the shortest exact form.
   - SQL: find a form that gives exactly the same digits for every input (for example `round(a::numeric / b::numeric, 16)` — check that Postgres's own division scale never drops below 16 digits before the `round`; if it can, cast an operand to a numeric with enough scale first). Prove it with differential cases including large and tiny values.
3. **`%`**: the sign of the left side (both runtimes already agree; pin it). For `DECIMAL` operands too.
4. **By zero**: `/` and `%` by zero are the evaluation error `eval.divisionByZero` in the interpreter; Postgres's `22012` counts as the same error in the harness.
5. **Spec §5.1**: the meaning of `+` for text, `/` and `%`, in a short table. **Showcase**: one example each.
6. **Cases**: remove `knownGap: 'C4'`; add `test/differential/cases/c4-operators.cases.ts`.

## Files

`src/language/minab-type-checker.ts`, `src/language/minab-interpreter.ts`, `src/language/minab-sql-compiler.ts`, `src/language/diagnostics/codes.ts`, differential cases, `test/typechecking.test.ts` (text `+` type rules), spec §5.1, showcase.

## Do not touch

`CAST` (C3). `FLOOR` (L5).

## Output

Operators that agree in both runtimes.

## Test scenarios

- `.first_name + " " + .last_name` interpreted = compiled.
- `"a" + null` is `null`; `"a" + 1` is a type error that mentions `CAST`.
- `7 / 2` = `3.5` for literals and for two `INTEGER` columns.
- `1 / 3` = `0.3333333333333333`; `2 / 3` = `0.6666666666666667`; `10000000000 / 3` agrees.
- `-7 % 3` = `-1`; `7.5 % 2` = `1.5`.
- `5 / 0` and `5 % 0` → `eval.divisionByZero` in both.

## Done when

No `knownGap: 'C4'` remains; the cases pass in both runtimes; spec and showcase updated.

## Not here

Integer division as a function (`FLOOR(a / b)` from L5).
