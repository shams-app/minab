## Goal

App code calls `run` and does not care where the program runs: programs of tier `local` run in the browser worker; programs of tier `data` go to the server **by program id** through the wire format. Logs show in the browser console either way. PGlite is available as an optional in-browser database for demos. The browser bundle is measured and guarded.

## Why now

Shamsine's M.10 (remote evaluation) and the browser example (H6) need it; the performance budgets (Q4) need the bundle numbers.

## Build

1. **`createRemoteMinab({ endpoint, fetch?, headers? })`** in `src/browser/remote.ts`: `run` for **stored programs** (`{ id, version }`) sends a wire v1 request; batches runs made in the same tick into one request (up to the batch limit); `AbortSignal` aborts the `fetch`; answers decode with R6.
2. **`routeByTier({ local, remote })`** in `src/browser/route.ts`: given a stored program (id, version, source) prepared locally, runs it locally when its analysis tier is `local`, otherwise sends it to `remote` by id. Never sends SQL or a schema (D28).
3. **Logs**: a `consoleEventSink()` for local runs; for remote runs, the `logs` in each result are passed to the same sink, so the developer sees them the same way.
4. **PGlite data port** (`./browser/pglite`, replacing R2's stub): creates a PGlite database (optional peer), loads `citext`, creates tables from a schema (`src/host/ddl.ts`), and returns a `DataPort`. For demos and offline playgrounds only.
5. **Bundle guard**: `scripts/browser-bundle.mjs` builds a tiny app that imports `./browser` and the worker (esbuild, browser platform) and writes gzip sizes to `bench/bundle.json`; it **fails if any Node-only module** (`pg`, `node:*`, `langium/node`, `vscode-languageserver/node`) appears in the bundle (esbuild metafile). Run it in a new workflow `browser-bundle.yml`. Record the numbers in your status file (Q4 sets the budget from them).

## Test scenarios

- A local-tier rule runs with zero `fetch` calls.
- A data-tier rule sends exactly one request with `program.ref` and the inputs, and no SQL.
- Ten runs in one tick → one batched request; the answers reach the right callers.
- Abort during a remote run → `cancelled`, and the `fetch` was aborted.
- Remote logs arrive in the console sink.
- The bundle guard fails if you import `src/node/` from `src/browser/` (try, undo).

## Done when

The tests pass; the bundle workflow is green and its numbers are recorded.
