# H1 — Node adapters, transactions and the CommonJS build

| Lane | Kind | Size | Depends | Decisions | Release |
|---|---|---|---|---|---|
| H — Hosts | Mechanical | M | [R7](R7.md) | [D32](../decisions.md#d32), [D06](../decisions.md#d06), [D09](../decisions.md#d09) | 0.3.0 |

## Goal

A Node app can give Minab its database in one line — from `pg`, from TypeORM's `dataSource.query`, from Prisma's `$queryRawUnsafe` — including the transaction the request is already in. The package works from ES-module projects, from CommonJS projects (NestJS's default), from Jest, and from Bun.

## Why now

The NestJS module (H2) and writes (X5) build on these adapters. Shamsine's `core/service` is NestJS, tested with Jest, and runs Bun: each must load the package.

## Build

1. **`src/node/`**:
   - `pgDataPort(clientOrPool)` (from R7);
   - `queryFunctionDataPort((text, params) => Promise<rows>)`: plugs TypeORM (`dataSource.query`, or a `QueryRunner`'s `query`) and Prisma (`$queryRawUnsafe`) without depending on them. Minab's statements use Postgres `$1` placeholders; say so in the README (a driver that wants `?` must translate);
   - `systemClock(timeZone?)`;
   - README: how to pass the request's transaction (create the data port per request from the transaction's query function).
2. **CommonJS bundle** (D32 option a): `scripts/build-cjs.mjs` with esbuild bundles `.`, `./node` and `./nestjs` into `out/cjs/*.cjs` (Langium and its dependencies inlined; `pg`, `@nestjs/*`, `rxjs`, `reflect-metadata` kept external). Add `require` conditions for those three entries in `package.json` `exports` (H1 is the only phase allowed to add them). `build:release` runs it. The `./nestjs` bundle is built from whatever `src/nestjs/` holds (R2's stub until H2).
3. **Consumer smoke tests** (`test/consumers/`, with a README), run by a new workflow `consumers.yml` and locally with `npm run test:consumers`. Each packs the package (`npm pack`) into a temporary folder and installs the tarball:
   - an ES-module Node project: `import { createMinab } from '@shamsine/minab'` and `@shamsine/minab/node`; prepare and run a rule;
   - a CommonJS Node project: the same with `require`;
   - a Jest test in a CommonJS project (default Jest config) that requires the package and runs a rule;
   - Bun (`oven-sh/setup-bun` in CI): `bun run` a script that imports the package;
   - a TypeScript project with `moduleResolution: node` (old style, like many NestJS projects) that type-checks an import of `@shamsine/minab/node` (proves `typesVersions`).
4. `engines` stays as Q1 set it; the README of `src/node/` names the supported Node versions.

## Files

`src/node/*`, `scripts/build-cjs.mjs` (new), `package.json` (`exports` `require` targets, scripts, `esbuild` dev dependency), `test/consumers/*` (new), `.github/workflows/consumers.yml` (new), `test/node-adapters.test.ts` (new, against PGlite or `pg` with `MINAB_TEST_DATABASE_URL`).

## Do not touch

The NestJS module (H2). Write support in the adapters (X5 adds it).

## Output

Node adapters and a package that loads everywhere Shamsine runs.

## Test scenarios

- `queryFunctionDataPort` with a fake function receives `$1`-style SQL and params.
- `pgDataPort` against PGlite's `pg`-compatible API or a real Postgres: a correlated rule runs.
- A transaction: begin, run a rule through a data port bound to the transaction's client, see the rows the transaction inserted, roll back.
- All five consumer projects pass.

## Done when

The adapters are tested; the CommonJS bundle builds and is in the tarball; the consumer workflow is green.

## Not here

NestJS (H2), browser (H4), writes (X5).

## Later

None expected.

## If it grows

The Bun and old-`moduleResolution` consumers may move to Later only with the owner's OK (Shamsine uses both: they are important).
