# X4 — Loops, `.$index` and tuples

| Lane | Kind | Size | Depends | Decisions | Release |
|---|---|---|---|---|---|
| X — Execution | Mechanical | M | [X3](X3.md) | [D36](../decisions.md#d36) | 0.4.0 |

## Goal

All three loop forms run, with labeled `break` and `continue`, guarded by the loop-iteration limit. `.$index` works on array sources. Tuples run (or are clearly labeled). The `overdue-loop` example runs and gives its documented answer.

## Why now

These are the largest "parses, checks, refuses to run" block left without writes. X3's statement runner is the base.

- `src/language/minab.langium`: `LoopStatement`, `StepClause`, `WhereGuard`, `BreakStatement`, `ContinueStatement`, `TupleLiteral`, `TupleAccess`
- `src/language/minab-interpreter.ts` (X3's statement runner; the `.$index` refusal)

## Ask first

Before implementing tuples: run the tuple examples from spec §7.6 and the showcase through `minab run` and see what happens today. If the spec's meaning is clear, implement it. If it is not clear, stop and ask (with a recommendation).

## Build

1. **Loops** (spec §9.4): `loop i from a to b [by step | where cond] { … }`, `loop x in iterable [where cond] { … }`, `loop cond { … }`. Each iteration pushes a frame. `break`/`continue` with or without a label. A loop's tail value is discarded.
   - `iterable` may be an array value or a collection: a collection over a table reads its rows through the data port (one statement, then loop in memory; the row limit applies).
   - Each iteration counts toward `limits.loopIterations` (R4); over it → `limit.tooManyIterations`.
2. **`.$index`** (§3.5) inside a filter or loop over an array: the element's position (as the spec defines: check 0- or 1-based there). On a table collection: a check error if the checker can tell, otherwise `eval.indexNeedsArray`.
3. **Tuples** (§7.6): literals and positional access run as the spec says (after Ask first).
4. **`examples/overdue-loop`**: change its `expected.json` from `check-only` to `run` with the documented answer (the examples test asserted it was refused: that was on purpose; now update it). Update README output blocks only if the examples test checks one.
5. **Playground**: remove loops, `.$index` and tuples from the check-only list; cheat sheet; the overdue example in the gallery runs.
6. Tests (`test/loops.test.ts` new) and differential cases where a loop's result can be compared with a query.

## Test scenarios

- `loop i from 1 to 5 by 2` visits 1, 3, 5; `where i != 3` skips 3.
- `loop o in .orders where .status == "open" { … }` reads the orders once.
- Labeled `break outer;` from an inner loop leaves both.
- `continue` skips the rest of one iteration.
- `loop true { }` → `limit.tooManyIterations`.
- `.$index` on an array literal filter keeps the right elements.
- `overdue-loop` runs and prints its documented answer.

## Done when

No "not executed yet" refusal remains for any non-write construct; `overdue-loop` runs; tests and playground green.
