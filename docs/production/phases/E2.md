# E2 — Language server: a schema per document, completion and hover

| Lane | Kind | Size | Depends | Decisions | Release |

## Goal

The language server finds the right `minab.config.json` for **each** document, reloads it when it changes, and offers completion, hover, go-to-definition and signature help from `src/editor/`. An automated test drives the real server over stdio.

## Why now

Today one config is read at startup and shared by every open file, so two folders with different schemas get the wrong one, and a schema edit needs a restart. E1 made the features ready to wire.

## Read

- `src/language/main.ts` (header comment: why one config today), `src/cli/config.ts` (`discoverConfig`, `loadConfigFile`)
- `src/language/minab-module.ts`, `src/runtime/` README (the service cache)
- `src/editor/` README (E1)
- `test/lsp.test.ts`
- `vscode-extension/src/extension.ts` (what it registers; file watching)

## Ask first

None.

## Build

1. **A schema per document**: for each document, walk up from its folder to the nearest `minab.config.json` (as the CLI does); keep one set of language services per config file (reuse R2's cache keyed by config path + content hash). Documents without a config use an empty schema (as today).
2. **Watch configs**: register `workspace/didChangeWatchedFiles` for `**/minab.config.json`; on change, rebuild that config's services and re-validate its open documents. The VS Code extension already forwards file events if registered (check `extension.ts`; adjust it only if needed).
3. **Features**: completion (trigger characters `.`, `#`, `(`), hover, definition, signature help, all from `src/editor/`, converted to LSP types.
4. **`./lsp` entry**: export `startMinabLanguageServer(options)` (R2 put a minimal export there); `src/language/main.ts` calls it.
5. **Automated stdio test** (`test/lsp-stdio.test.ts`): spawn `node out/src/language/main.js --stdio` (after build), talk JSON-RPC with `vscode-languageserver-protocol` (already a dependency of `vscode-languageserver`): `initialize`; open two documents in two temp folders with **different** configs; assert their diagnostics differ correctly; request completion after `.` and get the right columns; hover; change one config file and see its document's diagnostics update; `shutdown`/`exit`.

## Files

`src/language/main.ts`, a new `src/lsp/` folder (server setup, config discovery and watching, LSP adapters for `src/editor/`) with a README, `src/runtime/` (if the cache key needs a path), `vscode-extension/src/extension.ts` (only if file watching needs it), `test/lsp-stdio.test.ts` (new), `test/lsp.test.ts`.

## Do not touch

Symbols, rename, semantic tokens, code actions (E3). Extension packaging (E4).

## Output

A language server that is correct with many schemas and useful while typing.

## Test scenarios

Listed in Build 5. Also: a document moved between folders picks up the new config on reopen.

## Done when

The stdio test passes in CI; two folders with different schemas both check correctly; typing `.` offers columns.

## Not here

E3's extras. The extension's Marketplace work (E4).

## Later

None expected.

## If it grows

Signature help may move to E3. The stdio test and per-document schemas must stay.
