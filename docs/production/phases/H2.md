## Goal

A NestJS app adds `MinabModule` and gets an injectable `MinabService` that prepares and runs programs with the request's ports, an exception filter that turns Minab errors into HTTP answers, a logger adapter, and an optional run endpoint that speaks the wire format and runs **stored programs by id**.

## Why now

Shamsine's `core/service` (cards M.6–M.8) is NestJS. The example app (H3) and the browser's remote runs (H5, H6) need the endpoint.

## Build

1. **`src/nestjs/`** (with a README), compiled with its own `tsconfig.nestjs.json` (decorator options) referenced by the root build:
   - `MinabModule.forRoot({ schemaLoader, functions, inputs, limits, programStore?, logs?, endpoint? })` and `forRootAsync({ useFactory, inject })`. `schemaLoader(context)` returns the schema for a request (per tenant or application) with its `version`;
   - `MinabService`: `prepare(source, options)`, `run(prepared, inputs, ports, options)`, `runStored(programId, version, inputs, ports, options)` (looks up the `ProgramStore`, caches prepared programs by id and version — D34);
   - `MinabExceptionFilter`: maps codes to HTTP: check failures (diagnostics) → 422 with codes and ranges; `limit.*` → 422; `cancelled` → 499 (client closed); `data.error` → 500 **without SQL text or stack**; `wire.*` → 400; unknown program → 404;
   - `MinabLogger`: an `EventSink` that writes `log` events (and, at debug level, `statement` events) to Nest's `Logger`, tagged with program id and request id. **Off by default when `NODE_ENV=production`** (D37), capped (D36), every value on one line (newlines escaped);
   - `MinabRunController` (only when `endpoint` is set): `POST <path>` with a wire v1 request; runs **stored programs only** (`program.ref`); `program.source` is refused unless `endpoint.allowSource: true` (meant for development; default false); batch size limit; uses the server's own schema and ports, never anything from the client.
2. Dev dependencies and optional peers per D09 (`@nestjs/common`, `@nestjs/core`, `@nestjs/testing`, `rxjs`, `reflect-metadata`).
3. Unit tests with `@nestjs/testing` (`test/nestjs/*.test.ts`): module setup (sync and async), service prepare and run, `runStored` cache, each exception mapping, logger behavior, the controller (stored program OK; source refused; source allowed in dev mode; 101 runs refused).
4. The CommonJS bundle (H1's script) now includes the real `./nestjs`; the consumer workflow gains a small Nest CommonJS consumer that boots a module with `MinabModule.forRoot` (extend H1's consumer folder with one new project).
