# C2 — Exact `DECIMAL` numbers

| Lane | Kind | Size | Depends | Decisions | Release |
|---|---|---|---|---|---|
| C — Correctness | Design → Mechanical | M | [C1](C1.md) | [D17](../decisions.md#d17), [D09](../decisions.md#d09) | 0.2.0 |

## Goal

`DECIMAL` values are exact in the interpreter, as they are in Postgres. `0.1 + 0.2 == 0.3` is `true` in both runtimes. `INTEGER` math never silently loses precision. Decimal values leave Minab as exact strings.

## Why now

Shamsine stores money as `DECIMAL`. Every later number feature (CAST, division, `ROUND`) builds on the representation chosen here.

## Read

- `src/language/minab-interpreter.ts`: how number literals become values, `binary()`, `number()`, `equal()`, ordering
- `src/language/minab-types.ts` (numeric family helpers)
- `src/host/format.ts` (`formatValue`), `src/cli/main.ts` (`--json` output)
- How rows from the data port arrive (`src/cli/executors.ts`, `src/host/fixture-executor.ts`: `pg` returns `numeric` as a string)
- `test/differential/README.md`
- Decisions D17, D09

## Ask first

None (D17 is the approved proposal; `big.js` is on D09's list).

## Build

1. Add `big.js` (runtime dependency) and its types (dev).
2. **Representation**: a `DECIMAL` value inside the interpreter is a `Big`. An `INTEGER` value is a JavaScript number. A number literal with a fraction is a `DECIMAL`; without one, an `INTEGER`.
3. **Arithmetic and comparison**: `+`, `-`, `*`, unary minus, `==`, `!=`, `<`, `<=`, `>`, `>=`, `IN`, aggregates (`SUM`, `AVG`, `MIN`, `MAX`) on decimals are exact. `INTEGER` op `INTEGER` stays `INTEGER`; a mix is `DECIMAL`. Division and `%` stay as today here (C4 changes them), but they must accept `Big` values.
4. **Integer range**: any `INTEGER` result outside ±9,007,199,254,740,991 is an evaluation error `eval.integerOutOfRange` (add the code to the registry; runtime errors become fully structured in R4, so for now the code goes into the message or a field your interpreter already returns).
5. **Values in**: rows from the data port and the record under validation are normalized by column type: a `DECIMAL` column value (string or number) becomes a `Big`; an `INTEGER` value given as a string or `bigint` becomes a number, or the range error.
6. **Values out**: a `DECIMAL` result leaves the interpreter as a string in its shortest exact form (no exponent, no trailing zeros: `"0.3"`, `"170"`). `formatValue` prints it plainly; `--json` prints it as a JSON string. Numbers inside `JSON` values stay JSON numbers.
7. **SQL parameters**: a `DECIMAL` parameter is bound as a string (Postgres reads it exactly).
8. **Tests and docs**: remove `knownGap: 'C2'` from C1's cases; add `test/differential/cases/c2-decimal.cases.ts` (money values, many digits, negative values, comparisons across `INTEGER`/`DECIMAL`). Update `examples/*/expected.json` where a decimal result now prints as a string (for example `discounted-total`). Spec §7.2: one paragraph on exactness and on how values leave Minab (approved by D17).

## Files

`package.json`, `src/language/minab-interpreter.ts`, `src/language/minab-types.ts` (if needed), a new `src/language/values.ts` (number helpers, if it keeps the interpreter readable), `src/host/format.ts`, `src/language/diagnostics/codes.ts`, differential cases, affected `examples/*/expected.json`, spec §7.2, and a root `README.md` output block only if `test/examples.test.ts` checks it and its text changes (that block only; see the protected-files rule).

## Do not touch

`CAST` (C3). Division and `%` semantics (C4). The wire format (R6).

## Output

Exact numbers that C3, C4, L5 and R6 build on.

## Test scenarios

- `0.1 + 0.2 == 0.3` is `true` interpreted and compiled.
- `12345678901234567890.12 + 0.01` is exact.
- `.price * .quantity` with `price = "8.30"` from the data port gives `"24.9"` for quantity 3.
- `9007199254740991 + 1` → `eval.integerOutOfRange`.
- `SUM` over decimal rows is exact.
- `minab run --json` on `discounted-total` prints the documented string.

## Done when

No `knownGap: 'C2'` remains; the cases pass in both runtimes; examples and spec updated; root and playground green.

## Not here

`CAST` (C3), division and `%` (C4), how values cross the wire (R6 uses this representation).

## Later

None expected.

## If it grows

Everything is required. If the interpreter changes are large, move the number helpers to `src/language/values.ts` (it does not count as extra scope).
