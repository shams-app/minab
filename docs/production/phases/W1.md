## Goal

The playground's look is designed and approved in Claude Design, and a short handoff note tells the build phases (W2, W3) exactly what to build. No code.

## Why now

It needs only the owner's site decisions (D40) and can run during all the language and runtime work. The build (W2) comes later.

## Read

- `playground/design/README.md` (Steps A–E), `playground/design/brief.md`, `playground/design/contract.md`, `playground/design/flows.md`, `playground/design/screens.md`, `playground/design/prompts.md`
- `playground/src/styles/tokens.css` (the token contract)
- Decision D40

## Ask first

Confirm the D40 answers are still right (brand direction, name story, domain, portfolio URL, social handles, site languages). At the sitting (A2) the owner chose brand **(B) "Terminal Noir"**, not the brief's recommended (A), and the domain `minab-lang.org`; the name story, the portfolio URL and the social handles were moved to this phase: ask them now and write the answers under D40. Also ask: does the site keep a light theme next to the dark one? (Recommended: yes, dark is the default.)

## Build

1. **Update the design inputs first** (they are older than this plan):
   - `brief.md`: fill in the D40 answers; tick the open items; the brand direction is (B) "Terminal Noir": change the brief and the Claude Design prompts that assumed (A) "Instrument" so they describe (B);
   - `screens.md` and `prompts.md`: add a **Console** tab next to Execution (L7: log lines, each linking to a source range); show **error codes** in the Problems list (B1); include **one Persian example program** (L3) in the gallery screens (code is left-to-right; Persian names inside it); mention exact decimals in the output (strings like `"24.90"`); keep everything else.
   - `src/content/landing.ts`: `footer.authorUrl` from D40 (the one `TODO(hamed)`). This is content, allowed by the contract.
2. **Steps B–D** of `playground/design/README.md` with the owner: set up the Claude Design project, run prompts 0–14 in order, iterate until the owner approves each screen group. The owner drives Claude Design; the session prepares and adjusts the prompts and keeps notes.
3. **`playground/design/handoff.md`**: what was approved, per screen group: layout, tokens (names and values), component states, copy changes, keyboard behavior, motion. W2 and W3 build from it (plus the Claude Design handoff bundle, Step E).
4. Status: **`waiting for approval`** until the owner approves the designs and the note.
