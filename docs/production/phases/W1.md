## Goal

The playground's look is designed in Claude Design and approved by the owner. A short handoff note (`handoff.md`) tells the build phases (W2, W3) exactly what to build. No code.

## Why now

It needs only the owner's site decisions (D40) and can run during all the language and runtime work. The build (W2) comes later.

## How this phase works (for the owner)

**You paste one prompt, in one place. The session does the rest and sends you links.**

| Step | Who | Where | What |
|---|---|---|---|
| 1 | You | **Claude Code**: claude.ai/code in the browser, or the **Code** tab in the Claude desktop app. New session, repository `shams-app/minab`. | Paste the **W1** prompt from [`prompts.md`](prompts.md). |
| 2 | Session | Same chat | Asks you 4 short questions in one message. You answer in the chat. |
| 3 | Session | Same chat | Builds each design round in Claude Design and sends you **a link**. |
| 4 | You | Open the link (it opens in claude.ai, browser or desktop app) | Look at the design. Then reply in the **Claude Code chat**: "approved", or what to change. |
| 5 | Session | Same chat | Changes the design until you approve. Then the next round. |

You do **not** need to: open claude.ai/design, paste the design briefs, take or upload screenshots, link the GitHub repository in Claude Design, or run `/design-sync`.

**The four rounds** (the session stops for your "approved" after each one):

1. **Design system:** wordmark, colors (dark and light), syntax colors, fonts, core components. Brief 1.
2. **The app:** landing page, workbench, output states, host panel. Briefs 2–5.
3. **The other pages:** tour, gallery, reference, embed, mobile, overlays, icons, motion. Briefs 6–13.
4. **Check and hand off:** the audit (brief 14) and `handoff.md`.

**If you stop in the middle:** the session commits and pushes after each round. Later, start a new Claude Code session and paste the **Continue W1** prompt from [`prompts.md`](prompts.md).

**If the session cannot create a Claude Design canvas** (it will tell you): open claude.ai (browser or desktop app) and start a new chat. In the message box, choose **Output → Design**, or open the **Artifacts** tab and pick the **Design** template. Paste the one text the session gives you, then paste the design's link back into the Claude Code chat. Do this once per round.

## Ask first

Ask these **four** questions in one message. Show the recommendation for each.

1. **The name's story:** what does "Minab" mean? One line for the landing page.
2. **Portfolio URL**, for the footer.
3. **Social handles** for the launch posts (they can say "later"; W5 uses them).
4. **Light theme:** keep a light theme next to the dark one? Recommended: yes, dark is the default.

Write the answers under D40. Everything else in D40 is already answered (brand **(B) "Terminal Noir"**, domain `minab-lang.org`, English plus one Persian example). Do not ask about them again.

Do **not** ask the owner how to set up Claude Design, whether to link the repository, or about screenshots. This card decides those (see Build).

## Build

1. **Update the design inputs first** (they are older than this plan). Commit this before round 1.
   - `brief.md`: fill in the D40 answers; tick the open items. The brand is (B) "Terminal Noir": change the parts of `brief.md` and `design-briefs.md` that assumed (A) "Instrument" so they describe (B). In brief 1, keep only direction (B).
   - `screens.md` and `design-briefs.md`: add a **Console** tab next to Execution (L7: log lines, each linking to a source range); show **error codes** in the Problems list (B1); include **one Persian example program** (L3) in the gallery (code is left-to-right; Persian names inside it); show exact decimals in the output (strings like `"24.90"`); keep everything else.
   - `playground/src/content/landing.ts`: `footer.authorUrl` from D40 (the one `TODO(hamed)`). This is content, allowed by the contract.
2. **The design rounds** (the four rounds above):
   - Create **one** Claude Design canvas for the whole site with the Artifact tool: run `quickstart` with intent `design`, then start from the **Design** type it names. Title: "Minab Playground". Put brief 0 (the context primer) in it first, then add each round's briefs as new artboards on the same canvas. Use no external design system: brief 1 creates it.
   - If you want to see the running app, run it yourself (`cd playground && npm ci && npm run dev`) and take screenshots with the pre-installed Chromium. Keep them in your scratchpad, never in the repository, and never ask the owner for them.
   - After each round: send the owner the link and a short list of what to look at (at most 5 lines). Wait for "approved" or change requests. Read any comments the owner left on the canvas. Apply the changes on the same canvas.
   - After each approved round: write that round's decisions into `handoff.md`, then commit and push. After round 1, open the pull request as a **draft**, so a later session can find the branch.
   - **Fallback:** if you have no Artifact tool or the Design type is not listed, say so in one line. Then, for each round, give the owner **one** text to paste: brief 0 plus that round's briefs, in a single code block. Follow "If the session cannot create a Claude Design canvas" above.
3. **`playground/design/handoff.md`**: the canvas link at the top. Then, per round: what was approved (layout, tokens with names and values for both themes, component states, copy changes, keyboard behavior, motion). W2 and W3 build from this file and the canvas.
4. Status: **`waiting for approval`** after round 4, until the owner approves the designs and `handoff.md`.

## Test scenarios

- The playground tests still pass after the `landing.ts` change (`cd playground && npm ci && npm test && npm run build`).

## Done when

The owner approves all four rounds and `handoff.md` (they set the status to `done`).

## Not here

Building the design (W2, W3). Keeping the design and code in sync (`/design-sync`): that is useful only after W2, when the real components exist.

## Later

A Persian version of the site (post-1.0, D40).

## If it grows

Design rounds take as long as they take. Each approved round is committed, so the phase can stop and continue in a new session at any round.
