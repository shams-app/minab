# Q1 — CI that catches real bugs

| Lane | Kind | Size | Depends | Decisions | Release |
|---|---|---|---|---|---|
| Q — CI, release and quality | Mechanical | S | [A1](A1.md), [A2](A2.md) | [D06](../decisions.md#d06), [D07](../decisions.md#d07) | 0.2.0 |

## Goal

Every push runs the full test suite against a **real Postgres**, on the supported Node versions, builds the VS Code extension and checks what goes into it, and checks dependencies for known security problems. npm is the main package manager, and CI keeps the bun lockfiles in sync (D07).

## Why now

Three known bugs only show against a real database, and `test/postgres.test.ts` is skipped on every push today. With this in place, the correctness phases arrive with proof.

None.

## Build

1. **`ci.yml`** (`language` job): a Node matrix per D06 (default: 22 and 24). Keep `npm ci`, `npm run build`, `npm test`. The `playground` job stays on one Node version.
2. **New workflow `postgres.yml`**: `services: postgres:16` (the official image has `citext`), `MINAB_TEST_DATABASE_URL` set, runs `npm test` with `MINAB_REQUIRE_DATABASE=1`.
   - In `test/postgres.test.ts` (and later database tests): when `MINAB_REQUIRE_DATABASE=1` and no URL is set, **fail** instead of skipping. So the job can never pass by skipping.
3. **New workflow `extension.yml`**: build the root (the extension bundles `src/language/main.ts`), then `cd vscode-extension && npm ci && npm run build && npm run package`; upload the `.vsix` as an artifact.
4. **`.vsix` content guard**: `vscode-extension/scripts/check-vsix.mjs` lists the entries of the built `.vsix` (it is a zip; use `npx @vscode/vsce ls` or `unzip -l`) and fails unless it **contains** `extension/package.json`, `extension/server/main.mjs`, `extension/syntaxes/minab.tmLanguage.json`, `extension/language-configuration.json`, `extension/README.md`, `extension/LICENSE`, and **does not contain** `extension/src/`, any `.map` file, or `node_modules` other than what the bundle needs. Run it in `extension.yml` after packaging.
5. **`engines`**: set `package.json` `engines.node` per D06 (default `>=22.12.0`). The README's "Requires Node.js" line is updated by V1 (README is protected); say so in your changelog fragment.
6. **Both lockfiles** (D07 = keep both): keep `bun.lock` and `playground/bun.lock`. New workflow `bun-lock.yml` (`oven-sh/setup-bun`): runs `bun install --frozen-lockfile` in the root and in `playground/`, so a stale `bun.lock` fails the pull request. If a lockfile is already stale on `main`, refresh it with `bun install` in this PR. In `CLAUDE.md`, change only the house-rule line "npm only. Do not use bun or yarn, and do not commit their lockfiles." to: "npm is the main package manager (CI uses `npm ci`). When dependencies change, update `bun.lock` too (`bun install`). Do not use yarn." (this card allows that one line).
7. **New workflow `audit.yml`**: on pull requests that change a `package-lock.json`, and weekly: `npm audit --audit-level=high` for the root, the playground and the extension. A finding fails the job.
8. If a new job is red **on current `main`** because of a real bug, do not hide it and do not fix it here: stop and tell the owner which card owns the fix.

## Do not touch

Release workflows (Q2), lint (B1), any test expectations.

## Output

A pull request shows: language on two Node versions, playground, Postgres (6 tests run, 0 skipped), extension build with a checked `.vsix`, audit, bun lockfiles in sync.

## Test scenarios

- Locally: `MINAB_REQUIRE_DATABASE=1 npm test` without a URL fails with a clear message.
- With a local Postgres (or in CI): the six Postgres tests pass.
- Add `src/**` to the package locally (edit `.vscodeignore`), package, run the guard → it fails; undo.
- The Postgres job log shows the database tests ran (not skipped).
- Add a dependency to `package.json` locally without running `bun install` → `bun install --frozen-lockfile` fails; undo.

## Done when

All new workflows are green on this PR; `bun-lock.yml` checks both bun lockfiles; the CLAUDE.md line matches D07; `engines` matches D06.

Release automation (Q2). New database tests (C1, C7). Lint (B1).
