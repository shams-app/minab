# L6 — Date and time built-ins

| Lane | Kind | Size | Depends | Decisions | Release |
|---|---|---|---|---|---|
| L — Language | Design → Mechanical | M | [L5](L5.md), [R3](R3.md) | [D21](../decisions.md#d21) | 0.3.0 |

## Goal

`NOW()`, `TODAY()`, date parts and date arithmetic work, with time zones done right, and give the same answer in the interpreter and in SQL.

## Why now

Shamsine forms need "due date is before today" and "paid more than 30 days ago" at go-live. `NOW()` needs the clock port (R3), and the functions use L5's table.

## Read

- `src/language/minab-builtins.ts` (L5's table)
- `src/runtime/ports.ts` (the clock port from R3: `now()` and `timeZone`)
- How the interpreter holds `DATE`, `TIME` and `DATETIME` values today (search for them in `minab-interpreter.ts` and `src/host/format.ts`)
- Spec §7.2 (types), §5.3.1
- Decision D21

## Ask first

None (D21 is the approved proposal).

## Build

1. **Value representation** (write it into the interpreter's value code and the spec): `DATE` is a `"YYYY-MM-DD"` string; `TIME` is `"HH:MM:SS"` (with optional fraction); `DATETIME` is an instant (milliseconds since 1970 UTC) and leaves Minab as an ISO 8601 UTC string. Values from the data port (`pg` returns `Date` objects or strings) are normalized by column type.
2. **The run's time zone and `NOW()`**: both come from the clock port. `NOW()` is read once per run (all calls in a run return the same instant). In SQL, `NOW()` and `TODAY()` are **bound parameters** with the run's values, never the database's `now()`.
3. **Functions, exactly as D21 lists them**: `NOW`, `TODAY`, `YEAR`, `MONTH`, `DAY`, `HOUR`, `MINUTE`, `DATE_ADD`, `DATE_DIFF`, and `CAST(datetime AS DATE)` in the run's time zone.
   - Interpreter: date-only math with pure calendar functions (days from a civil date and back, no `Date` time-zone surprises). `DATETIME` parts and day-or-larger arithmetic in a time zone with `Intl.DateTimeFormat` (offsets per instant), so daylight-saving changes are handled.
   - SQL: `AT TIME ZONE $n` with the run's zone, `make_interval`/`interval` arithmetic, `date_part`, `date_trunc` as needed. Month ends clamp (Postgres does this already).
   - The unit argument must be a text literal from D21's list (`call.unknownDateUnit` otherwise).
4. **Differential cases** `test/differential/cases/l6-*.cases.ts` with a fixed clock: month ends (Jan 31 + 1 month), leap years (Feb 29), negative amounts, `DATE_DIFF` truncation, and time zones `UTC`, `Asia/Tehran` (no daylight saving since 2022 — a good test of the time zone data), `Europe/Berlin` and `America/New_York` across their daylight-saving changes.
5. **Spec**: §7.2 (what `DATETIME` is; the run's time zone), §5.3.1 rows. **Showcase** section. **Playground**: the host panel can set the time zone and a fixed "now" (in `src/state`/`src/hooks`, no UI redesign: a field in the existing host panel), cheat sheet entries.

`src/language/minab-builtins.ts`, `src/language/minab-interpreter.ts` (date values), a new `src/language/dates.ts` (calendar helpers), `src/language/minab-sql-compiler.ts`, `src/host/format.ts`, `src/language/diagnostics/codes.ts`, differential cases, `test/dates.test.ts` (new), spec, showcase, playground host settings and cheat sheet.

## Do not touch

The clock port's interface (R3 owns it; ask if it lacks something).

## Output

Dates that Shamsine can rely on; a clock that makes tests repeatable.

## Test scenarios

- `TODAY()` at `2026-03-20T21:00:00Z` is `2026-03-21` in `Asia/Tehran` and `2026-03-20` in `UTC`.
- `DATE_ADD("2026-01-31", 1, "month")` is `2026-02-28`; in 2028 it is `2028-02-29`.
- `DATE_ADD` of 1 day across Berlin's spring change keeps the wall-clock time; 24 hours does not.
- `DATE_DIFF("2026-10-02", "2026-09-01", "month")` is `1`; `DATE_DIFF` the other way is `-1`.
- `NOW()` twice in one run is the same; the SQL uses a parameter (assert the text has no `now()`).
- `DATE_ADD(.d, 1, "fortnight")` → `call.unknownDateUnit`.
- Interpreted = compiled for every case on PGlite.

## Done when

All D21 functions pass the differential cases in the four time zones; spec, showcase and playground updated.

## Not here

Jalali (Persian) calendar display (the host's job). Durations as a type (post-1.0, if ever).

## Later

None expected.

## If it grows

The playground host-panel time zone field may move to Later (lane W). If `DATETIME` arithmetic in day-or-larger units across daylight saving is still failing at twice the budget, stop and ask the owner before splitting.
