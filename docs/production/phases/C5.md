# C5 — `CITEXT` and `LIKE`

| Lane | Kind | Size | Depends | Decisions | Release |
|---|---|---|---|---|---|
| C — Correctness | Design → Mechanical | S | [C3](C3.md) | [D15](../decisions.md#d15) | 0.2.0 |

## Goal

A `CITEXT` column compares with text without a `CAST` and ignores case, in both runtimes. `LIKE` behaves the same in both runtimes on case and on the `%`, `_` and escape characters.

## Why now

Today every case-insensitive comparison needs `CAST(… AS CITEXT)`, and Postgres would compare `citext = text` case-sensitively if the compiler did not cast. `LIKE` agreement is only asserted in the interpreter. It edits spec §5.5 after C3.

## Ask first

None (D15 is the approved proposal).

## Build

1. **Checker**: `TEXT` and `CITEXT` are one text family for `==`, `!=`, `<`, `<=`, `>`, `>=`, `IN` and `LIKE` (like `INTEGER`/`DECIMAL` for numbers).
2. **Interpreter**: when either side is `CITEXT`, compare ignoring case (Unicode default case folding: compare `toLowerCase()` of both, or a fold helper; match what Postgres `citext` does on a UTF-8 database for the test cases).
3. **Compiler**: when one side is `CITEXT` and the other is `TEXT` (a column, a literal or a parameter), cast the text side to `citext` (`$1::citext`), so Postgres uses the case-insensitive operator. Same for `IN` lists and `LIKE`.
4. **`LIKE`**: `%` any run, `_` one character, `\` escapes the next character (Postgres's default). The interpreter must agree, including a pattern that ends with `\`. Case: sensitive for `TEXT`, insensitive when either side is `CITEXT`.
5. **Spec** §5.5 and §7.2 (approved by D15): the text family rule and when comparisons ignore case. Remove the `CITEXT` "known limitation" wording from wherever the spec has it (the CHANGELOG is V1's job).
6. **Cases**: `test/differential/cases/c5-citext-like.cases.ts` (needs a `CITEXT` column: the PGlite helper loads the extension).

## Output

## Test scenarios

- `.email == "Ada@Example.COM"` (`.email` is `CITEXT`) is `true` for `ada@example.com` in both runtimes; the compiled SQL casts the literal to `citext`.
- `.name == .email` (TEXT vs CITEXT) checks and ignores case.
- `.email IN ["ADA@EXAMPLE.COM"]` ignores case.
- A pattern with an escaped `%` (check how a backslash is written inside a Minab string literal first: the string value converter may already unescape `\%`) matches `"50%"` and not `"500"`; `_` matches exactly one character, including one Persian letter.
- `.status LIKE "SHIP%"` on a `TEXT` column is case-sensitive.

## Done when

The cases pass in both runtimes; the spec states the rule; no `knownGap: 'C5'` remains.
