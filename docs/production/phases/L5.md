# L5 — Built-ins with several arguments: text, null and number functions

| Lane | Kind | Size | Depends | Decisions | Release |
|---|---|---|---|---|---|
| L — Language | Design → Mechanical | M | [L1](L1.md), [C2](C2.md) | [D20](../decisions.md#d20), [D10](../decisions.md#d10) | 0.3.0 |

## Goal

Built-in functions can take several arguments, optional arguments and generic types, and Minab gains the text, null and number functions of D20. Each one gives the same answer in the interpreter and in SQL.

## Why now

Real validation rules need `LENGTH`, `TRIM`, `COALESCE`, `ROUND`. Shamsine's form rules need them for go-live. It needs exact decimals (C2) for `ROUND` and `ABS`, and D10's naming rule (L1).

## Ask first

If the differential cases show that `UPPER`/`LOWER` differ between JavaScript and the test database for non-ASCII letters (Postgres case mapping depends on the database's locale): (a) document it in the spec as "may differ for non-ASCII letters on databases without a UTF-8 locale", or (b) compile them in a locale-independent way if the database supports it. Recommended: (a), unless (b) is a one-line change that works on PGlite and Postgres 16. Ask only if you see the difference.

## Build

1. **Signature machinery** in `minab-builtins.ts`: each built-in is one table entry with `name`, `kind` (`aggregate` | `predicate` | `scalar`), parameters (type, optional, rest), a return-type rule (for example "same as argument 1", "nullable if any argument is nullable"), the interpreter function, and the SQL form. The eight existing built-ins move into the table with no behavior change. The checker, interpreter and compiler read the table; no per-name `switch` remains.
2. **New functions, exactly as D20 lists them**: `LOWER`, `UPPER`, `TRIM`, `LENGTH`, `SUBSTRING`, `REPLACE`, `STARTS_WITH`, `ENDS_WITH`, `CONTAINS`, `COALESCE`, `ROUND`, `ABS`, `FLOOR`, `CEIL`, `GREATEST`, `LEAST`.
   - `LENGTH` counts Unicode code points (`[...s].length`, not `s.length`), like Postgres `char_length`.
   - `TRIM` removes spaces, tabs and line breaks (SQL: `btrim(x, E' \t\r\n')`).
   - `STARTS_WITH`, `ENDS_WITH`, `CONTAINS` ignore case when either side is `CITEXT`. Their SQL must not treat `%` or `_` in the argument as wildcards (use `starts_with()`, `right()`, `strpos()`, or escape).
   - `ROUND` is half away from zero in both runtimes (Postgres `round(numeric, int)` already is; the interpreter uses `big.js` with that mode).
   - `GREATEST`/`LEAST` ignore `null`, like Postgres.
   - Wrong argument count → `call.wrongArgumentCount`; wrong type → the usual type codes.
3. **Differential cases**: `test/differential/cases/l5-*.cases.ts`, one file per group (text, null, number), with `null`, empty text, Unicode (`"سلام"`, emoji), negative numbers, half values (`2.5`, `-2.5`).
4. **Spec §5.3.1**: split the table into "Aggregates and predicates" and "Scalar functions"; add the D20 rows and the null rule. **Showcase**: one numbered section with an example per group.
5. **Playground**: cheat sheet entries; completion lists the new names (the playground reads the built-in table if it can; otherwise add them).

## Files

`src/language/minab-builtins.ts`, `src/language/minab-type-checker.ts`, `src/language/minab-interpreter.ts`, `src/language/minab-sql-compiler.ts`, `src/language/diagnostics/codes.ts`, differential case files, `test/builtins.test.ts` (new: checker and arity tests), spec §5.3.1, showcase, playground cheat sheet (and `intel.ts` only if it hard-codes the list).

## Do not touch

Date and time functions (L6). `LOG` (L7). The grammar (no change is needed: built-ins are names).

## Output

A table-driven built-in library that L6 and L7 extend.

## Test scenarios

- Every function: interpreted = compiled on PGlite for normal values, `null`, and edge values.
- `LENGTH("😀")` is `1`; `LENGTH("سلام")` is `4`.
- `CONTAINS("50%", "%")` is `true` and `CONTAINS("abc", "%")` is `false` in both runtimes.
- `ROUND(2.5)` is `3`, `ROUND(-2.5)` is `-3`, `ROUND(1.005, 2)` is `1.01` (exact decimals).
- `COALESCE(.nickname, .name)` has the type of `.name` and is not nullable when `.name` is not.
- `LENGTH(5)` → type error; `ROUND()` → `call.wrongArgumentCount`.
- All eight old built-ins behave exactly as before (existing tests unchanged).

## Done when

All D20 functions work in both runtimes with differential proof; the table drives checker, interpreter and compiler; spec and showcase updated; playground green.

## Not here

`NOW`, `TODAY`, date math (L6). `LOG` (L7). Host functions (R3).

## Later

More functions (for example `SPLIT`, `REGEXP_*`) only on request (post-1.0).

## If it grows

The table refactor (Build 1) and the functions are both required. If over budget, `GREATEST`/`LEAST` and `ENDS_WITH` may move to Later with the owner's OK (they are the least used).
