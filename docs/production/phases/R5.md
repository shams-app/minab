## Goal

Every prepared program says, before it runs, what it touches: tables, record fields, host inputs and functions, whether it can reach the data port at all (`needsData`), whether it writes, and its **tier** (`local`: safe to run in the browser with no data; `data`: needs the server). It also lists which record fields its result depends on, so a form can re-run only the rules a field change affects.

## Why now

Shamsine's M.2 needs exactly this, the browser router (H5) uses the tier, and the playground (R8) shows it. It only needs the prepared program (R2), so it runs next to R3 and R4.

## Build

1. `src/runtime/analyze.ts`, exposed as `PreparedProgram.analysis`:
   - `tables`: every table the program can read (`#T`, `FROM T`, relation traversal, subqueries);
   - `recordFields`: paths read from the record under validation (`.a`, `.b.c` where `.b` is a relation: the first step is a record field, the rest needs data), and whether `$` is read;
   - `inputs`, `hostFunctions`, `userFunctions`, `builtins` used;
   - `needsData`: true if any part can reach the data port (a table read, a relation traversal past the record, a host function not marked `local`);
   - `writes`: true if the program has `INSERT`/`UPDATE`/`DELETE` or record path assignment;
   - `tier`: `'local'` when `needsData` and `writes` are false; otherwise `'data'`.
2. **Conservative rule**: when the analysis cannot be sure, it says `data` (never the other way). Write the rule in the README.
3. **Proof by running**: a test runs every showcase, spec (parse-able) and example program that analysis calls `local` with a data port that throws; none may call it.
4. **Dependencies for re-runs**: `dependsOn(field)` or a list: which `recordFields` change the result. A form can re-run only the rules whose list contains the changed field.
5. Tests per construct family: sigils, relations, filters, aggregates, `#T`, subqueries, user functions (analysis follows calls), host inputs and functions, `if`/`switch` branches (both branches count), loops and DML (parse-level only until X runs them).

## Test scenarios

- `.end_date > .start_date` → `local`, `recordFields: [end_date, start_date]`.
- `COUNT(.orders[.status == "x"]) < 5` → `data`, tables `[Order]`.
- `.customer.name == "Ada"` → `data` (crosses a relation), `recordFields: [customer]`.
- `currentUser.id == .owner_id` → `local`, inputs `[currentUser]`.
- A local host function keeps `local`; a non-local one makes it `data`.
- A rule that calls a user `fn` that reads `#Order` → `data`.
- The "proof by running" test passes for every program called `local`.

## Done when

The analysis is exposed and tested; the proof test passes; the README documents each field.
