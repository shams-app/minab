## Goal

Spec §12 contains only items marked "post-1.0". The two "judgment calls" from old Phase 4 are written into the spec. A relation can be compared with a key directly (D25). A `GROUPBY` key can have a name (`AS`, the grammar half of D22).

## Why now

These change the language, so they belong before 1.0 freezes it, and after the grammar chain's earlier changes (L1, L3). It waits for C5 because it edits spec §5.5 after C3 and C5 did.

## Build

1. **§12, per D24**:
   - items 1, 2, 3: close each as "resolved" with the D24 answer, and add a test that pins the behavior (`NOT x == y` parses as `NOT (x == y)`; `a < b < c` is an error; the `CurrentRecord` shape);
   - item 4: document how to read the two `[...]` forms in the spec; keep the Chevrotain warning unless D24 says otherwise;
   - item 8: a second `let` with the same name in the same scope is an error (`scope.duplicateLet`); an inner block may shadow. Tests for both;
   - item 13: mark it "post-1.0";
   - item 17: `!` on a `collection` step is an error (`type.vivifyOnCollection`). The check only; writes come in X6.
2. **D25, a relation compared with a key**: `ref(T) == value`, `!=` and `IN` are allowed when the value has the type of `T`'s primary key. The checker types it; the compiler emits the foreign-key column (`"Order"."customer_id" = $1`, no subquery); the interpreter compares the record's key. Spec §3 and §7.7 text; one showcase example. Leave existing `.customer.id == x` examples as they are (both forms stay valid).
3. **D22, grammar half**: `GROUPBY` keys accept `AS name`: `keys+=GroupKey`, `GroupKey: expression=Expression ('AS' alias=Name)?`. Alias names must be unique (`query.duplicateGroupKeyName`). A single key works exactly as before, with or without a name. Do **not** implement multi-key `KEY` here (X2 does); its spec text also comes with X2. Update the compiler and checker only so existing programs keep working with the new AST shape.
4. **Judgment calls into the spec**: §5.5 "`INTEGER` and `DECIMAL` are one numeric family: they compare and combine without `CAST`" (if still true after C2); §5.4 "a query used as a scalar needs no `LIMIT 1`", with what happens when it returns several rows (as checked in Ask first).
5. §11 grammar block, `vscode-extension` grammar (generated), playground tokenizer and cheat sheet for `GROUPBY … AS`.
6. Showcase sections for D25 and the `GROUPBY … AS` syntax.

## Test scenarios

- The pinning tests in Build 1.
- `let x` twice in one scope → `scope.duplicateLet`; shadowing in an inner block works and the inner value is used.
- `.orders!.total = 1;` → `type.vivifyOnCollection`.
- `.customer == "cus-ada"` checks, compiles to the foreign-key column (assert the SQL text), and gives the same answer interpreted and compiled.
- `.customer == 5` (wrong key type) → a type error.
- `GROUPBY .status AS s SELECT KEY AS status, COUNT(.) AS n` works like `GROUPBY .status`.

## Done when

§12 has only "resolved", "retired" or "post-1.0" items; the listed tests pass; spec, showcase, grammar block and highlighters are in sync (L2's test passes).
