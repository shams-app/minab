# L1 — Call functions by name: remove `&`

| Lane | Kind | Size | Depends | Decisions | Release |
|---|---|---|---|---|---|
| L — Language | Design → Mechanical | M | [B1](B1.md) | [D10](../decisions.md#d10), [D11](../decisions.md#d11) | 0.2.0 |

## Goal

A user function is called `name(...)`, exactly like a built-in, and `&` leaves the language, its docs, its examples and the playground. Built-ins and user functions stay apart by D10's rule, and name clashes follow D11.

## Why now

0.2.0 is not published yet (no tag, npm 404). If this lands first, no public release ever teaches `&`, so there is nothing to deprecate. Every later phase writes calls (the differential tests, built-ins, the runtime, the editor), so doing this first saves churn.

## Ask first

None. D10 and D11, with their examples, are the approved proposal. If the work needs a grammar change beyond deleting `FunctionCall`, stop and ask.

## Build

1. **Grammar**: delete the `FunctionCall` rule and its `Primary` alternative. Run `npm run langium:generate`; it must print only the known `Postfix` warning. This also regenerates `vscode-extension/syntaxes/minab.tmLanguage.json`.
2. **Type checker**: `inferCallExpression` resolves the callee: a built-in first, otherwise a declared `fn` in scope. It absorbs `inferFunctionCall`. Remove every `&name(...)` hint from messages. A truly unknown name gives `call.unknownFunction` ("unknown function "foo"").
   - **Pitfall (from Phase 7):** a call's callee `NameRef` must never be type-inferred on its own; that produced false diagnostics once. Keep the callee position excluded everywhere.
3. **Validator**: drop `FunctionCall` from the registrations. Enforce D10 at `FunctionDecl` (`call.functionNameCase`: a `fn` name must contain a lowercase letter). Enforce D11 at `VariableDecl` and parameters (`scope.nameIsFunction`) and at `FunctionDecl` against schema table names (`scope.functionNameIsTable`). Add the codes to the registry (sorted).
4. **Interpreter**: `builtin()` sends a non-built-in name to `callFunction`. Remove the `isFunctionCall` branch and `&` from messages.
5. **SQL compiler**: a user-function call still **refuses** to compile (it must never emit `discounted(...)` as if it were a database function: that would be a wrong answer). Pin it with a test.
6. **Tests**: update the call sites in `test/` (about 14). Rewrite the old "item 10" tests, do not delete them: a bare user call passes; D10's rule is enforced; an unknown name gets `call.unknownFunction`.
7. **A future-built-in test**: register a test-only built-in `LOWER` in a test copy of the built-in table; a program with `fn lower(...)` still checks and runs (D10 keeps them apart).
8. **Examples**: `examples/discounted-total` and `examples/reconcile-overdue-accounts` (3 call sites).
9. **Spec and showcase** (approved by D10/D11): §5.3 (rewrite the "built-in vs. user-defined" paragraph with D10's rule), §8 preamble and §8.4 (every example), §11 (the grammar block, same as the `.langium` file), §12 item 10 (mark it "resolved, then revised 2026-09-24", keep its history the way item 9 keeps `yield`'s). `docs/showcase.md` (6 call sites).
10. **Rules**: `.cursor/rules/00-project-overview.mdc` (the line that says `&name(...)` calls a user function) and the `minab-builtins.ts` line in `.cursor/rules/language-implementation.mdc` ("never `&`-prefixed").
11. **Playground**:
    - `playground/src/syntax/tokens.ts` (tokenizes `&name`), `playground/src/monaco/language.ts` (`&` as a completion trigger), `playground/src/engine/intel.ts` (hover text and completion after `&`), `playground/src/engine/engine.ts` (the construct label);
    - content: tour lesson 10 (`lesson.md`, `starter.minab`, `solution.minab`, its goal in `tour/index.ts`), the cheat sheet, the landing snippet, the gallery examples, `playground/design/prompts.md` (2 mentions);
    - tests: `playground/test/engine.test.ts`, `playground/test/tokens.test.ts`.
12. **Drift guard**: `test/no-ampersand-calls.test.ts` fails if `&` followed by a name and `(` appears in any `.minab` file, any fenced code block in `docs/query-language-spec.md` or `docs/showcase.md`, or any file under `playground/src/content/`. History is allowed: `docs/roadmap.md`, `docs/status.md`, `docs/release-future/`, `docs/production/`, and spec §12 item 10's history text (allow that one paragraph by an exact marker, not by skipping the whole spec).
13. **Changelog fragment** (`type: changed`, `scope: language`, `breaking: false` because nothing was published): "User functions are called by name, like built-ins: `discounted(200, 15)`."

## Output

One way to call a function. A callee `NameRef` now resolves to its `FunctionDecl`, which E1 uses for hover and go-to-definition.

## Test scenarios

- `discounted(200, 15)` runs and gives `170` in `examples/discounted-total`.
- `fn SUM(...)`, `fn TAX(...)` → `call.functionNameCase`; `fn tax(...)` is fine.
- `let total: DECIMAL = 5;` next to `fn total(...)` → `scope.nameIsFunction`; a parameter with a function's name → the same code.
- `fn Customer()` with a `Customer` table → `scope.functionNameIsTable`.
- `foo(1)` → `call.unknownFunction`.
- `FROM Order WHERE discounted(.total, 10) > 5 SELECT .id AS id`: `compile` refuses with a clear reason, and the SQL text never contains `discounted(`.
- The future-built-in test (Build 7).
- `&foo(1)` is now a syntax error.
- The drift guard fails when you add `&x(1)` to a gallery example; remove it.
- Playground: engine, tokens and content tests green (lesson 10 starter fails its goal, solution passes).

## Done when

- `grep -rE '&[A-Za-z_]+\('` finds nothing outside the history files.
- Root, playground and extension builds and tests are green; `langium generate` prints only the known warning.
- D10 has a test that would catch a future built-in colliding with an existing `fn`.

## Not here

- Hover and go-to-definition on function names (E1, E2).
- A user `fn` inside a query (X2).

None expected.
