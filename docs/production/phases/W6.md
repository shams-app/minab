# W6 — Playground fixes: the Data panel follows the open example

| Lane | Kind | Size | Depends | Decisions | Release |
|---|---|---|---|---|---|
| W — Website | Mechanical | S | [W4](W4.md) | — | 1.0.0 |

## Goal

The playground's Data panel always shows the tables of the open example's dataset, also after a direct page load of `/play?example=…`. The theme hook reports the real theme. The playground lint covers all of `src`.

## Why now

V4 point 1 needs "no open bug in any status file's Later list", and the website is public. W5 found this bug and could not fix it (state and hooks were outside its card). When you open an example with a different dataset (the Persian one after the demo data), the Data panel keeps the old table and lists English `Customer` rows next to a Persian example. After a direct page load of `/play?example=…`, it shows `unknown table "Customer"` in red. The TV script avoids both by clicking the Persian table tab. W2 and W3 left two small items in the same folders: the theme hook, and 15 lint findings.

## Read

- The W5 status file (Later), the W2 status file (Later) and the W3 status file (Later)
- `playground/src/ui/host/DataView.tsx` (it selects the first table only when no table is active, and the SQL console starts with a fixed `SELECT … FROM "Customer"` text), `playground/src/ui/host/HostPanel.tsx`
- `playground/src/hooks/useHost.ts`, `playground/src/state/store.ts`, `playground/src/state/workspace.ts`, `playground/src/content/datasets/`
- `playground/src/hooks/useTheme.ts`
- `playground/package.json` (the `lint` script), `playground/tests/` (Playwright site tests), `playground/README.md`

## Ask first

None.

## Build

1. **The Data panel follows the dataset.** When the dataset changes, or the active table is not one of its tables, select the dataset's first table. The SQL console starts with a query on a table that the dataset has. A direct page load of `/play?example=<id>` for every gallery example shows that example's tables, with no red error.
2. **The theme hook.** `useTheme` reports `effective` from the theme the page really shows: when the OS states no preference, the CSS shows dark, so `effective` must say `dark`.
3. **Lint.** Fix the 15 findings in `src/engine/worker.ts`, `src/hooks/useCommands.ts`, `src/routes/*` and `src/content/types.ts` (`no-floating-promises`, `no-misused-promises`, one `consistent-type-imports`). Then widen the `lint` script to all of `src`.
4. **Tests.** A Playwright test in `playground/tests/`: open the demo example, then the Persian example, and see the Persian tables in the Data panel. Load `/play?example=<the Persian example>` directly, and see no `unknown table` text. The test must fail without the fix. A unit test for the theme hook if it has a unit test file, or a Playwright check of `effective`.

## Files

`playground/src/ui/host/DataView.tsx`, `playground/src/ui/host/HostPanel.tsx`, `playground/src/hooks/useHost.ts`, `playground/src/state/*` (only what the fix needs), `playground/src/hooks/useTheme.ts`, the files with lint findings, `playground/package.json` (the `lint` script), `playground/tests/*`, `playground/README.md`, `changes/W6.md`.

## Do not touch

The TV demo mode and the launch material (W5). The engine's behavior (`playground/src/engine/**`): fix only its lint findings.

## Output

A Data panel that matches the open example, and a playground lint over all of `src`.

## Test scenarios

Listed in Build 4. Also: switching back to an English example shows `Customer` again, and `npm run test:site` (W4's and W5's tests) still passes.

## Done when

- The tests in Build 4 pass and fail without the fix.
- `cd playground && npm run lint && npm test && npm run build && npm run test:site` all pass.
- `changes/W6.md`: type `fixed`, scope `playground`.

## Not here

A service worker for offline reloads, and a high-contrast theme (W5 Later: post-1.0).

## Later

None expected.

## If it grows

Build 3 (lint) may move to Later. Build 1, 2 and 4 must stay.
