## Goal

Minab 0.2.0 exists in public: on npm, as a tagged GitHub release with the `.vsix`, on the VS Code Marketplace and Open VSX, with an honest CHANGELOG and README. A human has opened the extension in a real VS Code.

## Why now

The language gives right answers (C1–C8), `&` is gone (L1), the spec is under test (L2), and the release is automated (Q2). Everything later builds on a released baseline.

## Read

- `docs/releasing.md` (Q2)
- `CHANGELOG.md` (the unpublished `[0.2.0] - 2026-09-19` section), `changes/*.md`, `README.md` (status and known limitations)
- `docs/roadmap.md` (Phase 9's status line)
- Decisions D03, D04

## Ask first

- "Is `main` the state you want to release as 0.2.0?" (Show the list of merged phases from `progress.md`.)
- "May I push the tag `v0.2.0` from this session after the release PR is merged, or will you push it?"

## Build

1. Check: every Depends is done; `main` is green in every workflow; `npm view @shamsine/minab` is still 404 (nothing published by mistake).
2. On a branch `release/v0.2.0`, PR titled `[V1] Release 0.2.0`:
   - `scripts/changelog.mjs --version 0.2.0 --date <today>`: the CHANGELOG's existing unpublished `[0.2.0]` section and the fragments become **one** 0.2.0 section (merge them by hand where needed; the old section described the 2026-09-19 package, which never shipped);
   - **Known limitations** in the CHANGELOG and README say the same thing, exactly: what still does not run — whatever lane X has not merged yet (statements in blocks and function bodies, loops, writes, `.$index`, `switch`/`is`/JSON literals inside a query, several `GROUPBY` keys with `KEY`, user functions inside a query) — and anything else still open (one config per language-server session until E2; names limited to ASCII until L3). Check each item against `main`, do not copy this list blindly;
   - README: the Node version line (Q1's `engines`), the install line, the status text;
   - `docs/roadmap.md`: Phase 9 "published as 0.2.0 on <date>";
   - the version stays `0.2.0` (no bump needed).
3. After the owner merges: push the tag `v0.2.0` (only if the owner said so; otherwise tell the owner the exact command: `git tag -a v0.2.0 -m "Minab 0.2.0" && git push origin v0.2.0`). Watch `release.yml` to green.
4. **Verify**, and write each result in your status file:
   - in a clean folder: `npx @shamsine/minab@0.2.0 --version`, then `check` and `run` on an example copied from the tarball;
   - the GitHub release has the notes and the `.vsix`;
   - the Marketplace and Open VSX pages exist (if their secrets were set).
5. **Manual VS Code check** (the owner, this was never done): install the `.vsix`, open an `examples/*/` folder, see highlighting, exactly one squiggle on a type error, hover and F12 on an `#alias`. The owner tells the session the result; record it.
