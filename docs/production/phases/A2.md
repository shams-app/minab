# A2 — Decision sitting

| Lane | Kind | Size | Depends | Decisions | Release |
|---|---|---|---|---|---|
| A — Start | Owner | S | — | all, D01–D45 | — |

## Goal

The owner answers every open decision in `docs/production/decisions.md`, in one sitting or a few. After this, no phase has to stop halfway for a design question it could have known about.

## Why now

Most phases use at least one decision. Answering them together is faster than answering them one by one inside 40 sessions, and the answers stay consistent with each other.

## Read

- `docs/production/decisions.md` (all)
- `docs/production/README.md` ("What production level means")
- For context, only when a decision needs it: `docs/query-language-spec.md` §5, §7.2, §12; `playground/design/brief.md` ("Brand direction", "Open items for Hamed")

## Ask first

"Do you want to go through the decisions one by one, or accept all recommendations and talk only about the ones you name?"

## Build

1. Go group by group: Product and process (D01–D09), Language (D10–D26), Runtime and hosts (D27–D39), Website and launch (D40–D45).
2. For each decision: show the question, the options, the recommendation and the example in a short form. Ask. Write the answer on the decision's **Answer** line: the option, the owner's own words if any, and the date. Example: `**Answer:** (a), but the default time zone is Asia/Tehran — 2026-10-03`.
3. If the owner wants to postpone a question to the phase that needs it, write `**Answer:** ask at phase <ID>`. That phase's "Ask first" then covers it.
4. **If an answer differs from the recommendation**, update the cards that the decision lists under **Blocks**: change their Build, Test scenarios and Done when to match. Keep the change small and say in your status file which cards you changed. If the answer makes new work that fits no card, write it under Later in your status file (with a suggested lane). Do not create cards: the owner decides.
5. If an answer changes the phase list (for example a phase is no longer needed), tell the owner and change `phases/README.md` only with the owner's OK, then run `node docs/production/tools/progress.mjs --check`.
6. Language decisions (D10–D26) with the recommended answer are the approved proposals of the spec-governance cycle. Say this to the owner once, at the start of the Language group.

## Files

`docs/production/decisions.md`; cards in `docs/production/phases/` only when an answer differs from the recommendation; `docs/production/status/A2.md`.

## Do not touch

Code, the spec, the showcase, `.cursor/rules/`.

## Output

All decisions answered (or explicitly moved to a phase). Cards match the answers.

## Test scenarios

- `node docs/production/tools/progress.mjs` shows "decisions answered: N of 45" with no open decision, except those marked "ask at phase".
- `node docs/production/tools/progress.mjs --check` passes.

## Done when

Every decision has an Answer line that is an answer or "ask at phase <ID>", and every card the answers affect has been updated.

## Not here

Implementing anything. Writing the spec (the implementing phases do that).

## Later

Whatever new work the answers create (listed in the status file).

## If it grows

Split the sitting across several days if needed: each sitting records its answers; keep `Status: waiting for approval` until the last group is answered.
