## Done
A developer can now embed Minab using only the docs. There is an embedding guide, a generated API reference that CI checks, one index page for all documents, and a README section that points to them.

- `docs/guides/embedding.md`: what Minab gives and what the host gives, the API in ten lines, the ports, where programs run, a NestJS walkthrough and a browser walkthrough (each cited file is a link to the example app), errors and codes, limits, logs, security, stored programs and versions.
- `typedoc.json`, `tsconfig.typedoc.json`, `npm run docs:api` (it generates the parser first), and the workflow `.github/workflows/docs-api.yml`. Warnings are errors. The output goes to `out/api/` (ignored by git).
- Doc comments on every public symbol that lacked one (about 120, in `src/runtime`, `src/language`, `src/node`, `src/nestjs`, `src/browser`, `src/monaco`, `src/editor`). Comments only, no behavior change.
- Some types that public signatures use are now exported as types from the entry points (`ColumnType`, `MinabColumnSchema`, `MinabTableSchema`, `ScalarType`, `LogicalTypeBase`, `InputTypes`, the editor result types, `MinabLineState`, `LineState`, `TokenType`). TypeDoc needs this. It adds no runtime code.
- `docs/README.md`: the index of every document.
- Root `README.md`: new section "Use Minab from your app", new status text (what runs, what is embeddable), and the Node version fixed to 22.12 (it said 20.10; `engines` says 22.12). The output blocks that `test/examples.test.ts` checks were not changed.
- `docs/releasing.md`: one section that says `docs:api` builds the reference and that W4 or V2 publishes it.
- `test/docs-links.test.ts`: every relative link in `docs/**/*.md` and the root README must point to a file that exists. It skips code and web links.
- `changes/G1.md`.

Choices:
- The guide follows the code and the READMEs, not the ADR, where they differ (for example `createMinab` takes `functions`, `inputs` and `ruleContext`; the HTTP table is the filter's table).
- `docs/security.md`, `docs/performance.md` and `docs/compatibility.md` do not exist yet (Q3, Q4 and Q5 are not merged). The guide and the index name them as planned, without a link, because the link test would fail. There is a short summary of each topic in the guide.
- TypeDoc requires a comment on classes, interfaces, type aliases, functions, methods and accessors. It does not require one on each property or constructor. Property names such as `ok` and `code` are plain, and there are about 150 of them. This is written in the guide.
- `languageVersion` is only stored today. The guide says Q5 builds the rules around it.
