## Done
Every Minab example in the spec and the showcase is now parsed by a test, and most are also type-checked. The grammar block in spec §11 is compared with `src/language/minab.langium`, so the two can no longer drift apart.

- `test/spec-examples.test.ts` (new). It finds every fenced block with no tag (or `minab`) in both documents. A block is named like `spec §6.1 #2`. By default each block is parsed and checked against the fixture schema. Three lists in the file hold the exceptions, each with a reason: `NOT_PROGRAMS` (templates, `...` placeholders, ✗ notes), `CHECK` (the context a block needs, declarations put in front, or parse-only), `ERRORS` (blocks wrong on purpose, with the expected diagnostic code). `PIECES` splits blocks that hold several separate lines or paragraphs.
- `test/fixtures/spec-schema.json` (new, with a `README.md`): the tables the examples use.
- §11 tests: the spec grammar block equals `minab.langium` (comments and whitespace ignored). A difference is printed as a rule-by-rule report. A second test proves the report works. The `entry Model` excerpt in §6.3 must be part of §11.
- Example fixes under the governance exception (the grammar and §6 are authoritative). **Please look at these:**
  1. Showcase §14: `daysSincePayment` is now defined where it is called (copied from `examples/reconcile-overdue-accounts`).
  2. Spec §6.2: `$ IN ("pending", ...)` is now `$ IN ["pending", ...]`. `IN` takes a collection (resolved earlier; a parenthesized list is a tuple).
  3. Spec §8.6: `recentOrders` had `ORDERBY`, `LIMIT` before `SELECT`. The grammar order is `SELECT`, `ORDERBY`, `LIMIT`.
  4. Spec §9.3: the "same effect as" `UPDATE` example had no closing `;`.
- `changes/L2.md` (type `fixed`, scope `docs`).
