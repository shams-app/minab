## Done
`registerMinab(monaco, { client })` in `@shamsine/minab/monaco` gives Monaco the Minab language in one call.
The parser work runs in the worker (H4).

- `src/editor/tokens.ts`: the tokenizer, moved from the playground. `playground/src/syntax/tokens.ts` re-exports it.
- `src/monaco/`: `register.ts` (markers with a 150 ms debounce, completion, hover, signature help), `language.ts` (tokens, scopes, brackets, comments, word pattern), `types.ts`, README with the RTL note (`dir="ltr"`).
- `src/browser/`: new `editor` request in the bridge (version 1, additive). The worker answers with `src/editor/`. `WorkerMinab` has `complete`, `hover` and `signatureHelp`.
- `monaco-editor` added as a dev dependency (types only). It was already an optional peer (D09).
- `scripts/browser-bundle.mjs` and `test/browser/imports.test.ts` now cover `./monaco` (8.5 KB, 3.5 KB gzip, no Monaco inside).
- Tests: `test/monaco/` (26 tests, fake Monaco and fake client, plus the real worker on a `MessageChannel`).

Differences from the card:
- The tokens provider is built on `tokenizeLine` and not on a declarative Monarch grammar. Monarch regexes cannot tell `.status` (a record column) from `x.status` (a member) without the tokenizer's state, so the playground and Monaco would colour code differently. The tests check the same cases the card lists (keywords, sigils, strings, backtick and Unicode names, comments).
- Signature help was done too (it did not need to move to Later).
