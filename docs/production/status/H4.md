## Done
A web app can run Minab in a Web Worker through `createWorkerMinab`. The parser stays off the main thread. The worker calls back to ports on the main thread and waits for the answer (decision D30).

- `src/browser/protocol.ts`: bridge version 1. Messages `create`, `prepare`, `compile`, `run`, `cancel`, `release`, `dispose`, `result`, `port-call`, `port-result`, `cancel-call`. Value encoding by declared type (R6), loose encoding where the type is not known. Errors cross as `{ code, message, range?, params }`.
- `src/browser/worker.ts`: `serveMinab(endpoint, { ports })`. It starts itself in a Web Worker. A port may live in the worker (`ports` option). If the main thread offers the port for a run, that one is used.
- `src/browser/index.ts`: `createWorkerMinab({ worker, schema, functions, inputs, ruleContext, limits, ... })` with async `prepare`, `compile` and `run`, `dependsOn`, `release` and `dispose`.
- New code `wire.workerFailed` in the registry (and `docs/reference/diagnostics.md`).
- Tests: `test/browser/bridge.test.ts` (21 cases, run with a `MessageChannel` pair) and `test/browser/imports.test.ts` (import guard for both entries).
- READMEs: `src/browser/README.md`, `test/browser/README.md`. Fragment: `changes/H4.md`.

Port calls are bounded by the run's wall time (the runtime already races them): a call with no answer ends with `limit.timeout`, and the port's signal is aborted through `cancel-call`.
