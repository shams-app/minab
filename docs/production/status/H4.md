## Done
A web app can run Minab in a Web Worker through `createWorkerMinab`. It has the same `prepare` and `run` as `createMinab`. The worker can call back to ports on the page and wait for the answer.

- `src/browser/index.ts` (entry `./browser`): `createWorkerMinab({ worker, schema, functions, inputs, limits, ... })` returns `{ prepare, dispose }`. `prepare` gives a `PreparedProgram` (diagnostics, `ok`, `kind`, `analysis`, `dependsOn`, `compile`, `run`). Host names and limits are checked on the page at startup, like `createMinab`.
- `src/browser/worker.ts` (entry `./browser/worker`): `serveWorker(endpoint, { ports?, maxPrograms? })`. It starts on `self` when the file is loaded in a Web Worker. A port can live inside the worker (give it in `ports`).
- `src/browser/protocol.ts`: bridge version 1, with `create`, `prepare`, `run`, `cancel`, `dispose`, `port-call`, `port-result`, `port-cancel`. Every request has an id. Errors cross as `{ code, message, range?, params }`.
- Ports on the page: `data`, `functions`, `clock`, `events`. The page runs only the methods on a fixed list. Cancel and timeout work as the card says (see Checks).
- Four new codes in the registry: `wire.badMessage`, `wire.programExpired`, `wire.workerFailed`, `wire.workerStopped` (and `docs/reference/diagnostics.md` regenerated).
- Tests: `test/browser/bridge.test.ts` (30), `test/browser/values.test.ts` (6). The import guard in `test/runtime-imports.test.ts` now also walks `src/browser/index.ts` and `src/browser/worker.ts`.
- `src/browser/README.md`, `changes/H4.md`.

Notes where I adapted the card:
- **Values.** The card says "R6's encoding". That encoding needs a type for each value, and a port call has none. So `protocol.ts` has `toWire` / `fromWire`, which tag decimals (as text) and dates (as ISO text) and use the same text forms as wire format v1. An object with its own `$minab` key is wrapped, so it cannot fake a tag. The runtime already returns decimals as exact text, so a result is the same with or without a worker.
- **Timeout code.** The card says `limit.timeout`, and that is the registry code. The wall time ends a waiting port call (the runtime already does this and aborts the signal). The worker also times out the clock read that happens before the run.
- **Clock.** `ClockPort.now()` is synchronous and the runtime reads it once per run. The worker asks the page for `now` and `timeZone` once, before the run, and gives the run a fixed clock.
- **Events** are one-way: the page does not answer them.
- **`compile()`** stays synchronous on the page: the worker compiles at prepare time and sends the result.
- **Port errors.** A `PortError` keeps its code. Any other error crosses as `data.error` with the SQLSTATE only, and the worker rebuilds an error with that SQLSTATE, so the runtime maps it the same as a local port. The text of a driver error never crosses.
- `cacheStats()` is not on the page handle (the cache lives in the worker).
