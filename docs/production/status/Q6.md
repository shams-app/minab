# Q6 A real release runs only from a version tag

Status: done
Date: 2026-10-11
Branch / PR: q6-release-from-tag

## Done
`release.yml` now publishes only from the tag `v<package.json version>`. A new guard script is the first step after checkout. A run it refuses stops before `npm ci`, so nothing is built or published. The GitHub release step uses the existing tag and never makes one.

- `scripts/release-guard.mjs` (and `release-guard.d.mts`): inputs are the ref type, the ref name, the dry-run flag (flags or `GITHUB_REF_TYPE`, `GITHUB_REF_NAME`, `DRY_RUN`) and the `package.json` version. A dry run is allowed on any ref. A real run is allowed only when the ref type is `tag` and the name is `v<version>` (a tag push, or a hand run on that tag to run a failed release again). A `--dry-run` value other than `true` or `false` is refused, so a typo never means "publish". A refused run prints a GitHub `::error::` and exits 1.
- `.github/workflows/release.yml`: the guard step replaces the old "Read the version and check the tag" step and also sets `VERSION`. It runs before `setup-node` (the runner's own Node is enough for a plain script). `gh release create "v$VERSION" ... --verify-tag --title "v$VERSION"`.
- `docs/releasing.md`: a table of what each kind of run does, how to run a failed release again (start **Release** on the tag with `dry-run` off), and "never with `dry-run` off on a branch". The script table lists the guard.
- `scripts/README.md` lists the new files.
- `test/release-scripts.test.ts`: 9 new tests (the 6 card scenarios, a branch named `v0.4.0`, reading `package.json` and the GitHub variables, a bad dry-run value).
