# P2 Compile a group expression to a SQL fragment

Status: done
Date: 2026-11-03
Branch / PR: claude/phase-p2-production-8o1231

## Done
A host can now turn a prepared group expression (P1) into one SQL expression, to put inside its own `SELECT … GROUP BY GROUPING SETS …`. For `SUM(.Revenue) - SUM(.Cost)` and `column = n => "b." + n.toLowerCase()` the fragment is `CAST((SUM((b.revenue)) - SUM((b.cost))) AS numeric)`. A differential test shows that Postgres and the interpreter give the same answer for every group.

- API: `PreparedProgram.compileGroupExpression({ column })` → `{ ok: true, sql } | { ok: false, error }` (`src/runtime/prepare.ts`, `src/runtime/types.ts`). The types `CompileExpressionOptions` and `CompileExpressionResult` are exported from `src/runtime/index.ts`. No new `exports` entry.
- Compiler: `MinabSqlCompiler.compileGroupExpression` (`src/language/minab-sql-compiler.ts`). It reuses `expression()`. Columns of the group row are holes that get the host's `column(name)` text, in parentheses. Literals are inline: numbers as exact text (`(-3)` for a negative), text with `'` doubled, `E'…'` when the text has a `\`. A NUL character is refused. `/`, `%` and `\` use `NULLIF(<divisor>, 0)`. `AVG` is `SUM / COUNT` with the `/` rule (D14), so it equals the interpreter to the 16th decimal (Postgres `AVG` keeps 20). Before the host text goes in, the fragment is checked for `SELECT`, `;`, `--`, `/*` and `"`. A match is refused with `compile.notSql`.
- New code `compile.notGroupExpression` (registry, `docs/reference/diagnostics.md`, `test/diagnostic-codes.test.ts`).
- Differential: `test/differential/cases/p2-group-expression.cases.ts` (19 cases). The harness (`test/differential/harness.ts`) has a new optional `group: { rows, sets }` field. Postgres runs the fragment over a `VALUES` list with `GROUP BY GROUPING SETS ((), (Region), (Region, Month))`. The interpreter runs on the rows of each group. `differential.test.ts` is not changed.
- Fuzz: `test/fuzz/group-fragment.test.ts`. Hostile text literals; each fragment goes into `SELECT <fragment> FROM (VALUES …) GROUP BY ()` and must give one row. A text answer must be one of the program's own literals.
- Query tests: a P2 block in `test/sql-compilation.test.ts` (shape rules, quoting, codes, calls to `column()`).
- Docs: `docs/reference/compile-group-expression.md` (API page), `docs/guides/shamsine.md` (the pivot from the SQL side, with the output for the three P1 rows), `docs/security.md` (host rule 13 and a checklist line: the `column()` text is trusted), READMEs of `src/runtime`, `test/differential`, `test/fuzz`. `changes/P2.md`.

Differences from the card:
- Type (answer 3): every number answer is wrapped in `CAST(… AS numeric)`, also an `INTEGER` one. Only a bare `COUNT(…)` keeps `bigint`. I first tried `bigint` for `INTEGER` answers, but the checker types `if COUNT(.Revenue) == 0 { -1 } else { SUM(.Revenue) }` as `INTEGER`, and a `bigint` cast would cut the decimals of the `SUM`. The differential test caught it.
- `AVG` is not Postgres `AVG` (see above). The card allows "any equal-meaning form".
- `test/differential/harness.ts` and `test/diagnostic-codes.test.ts` are not in the card's file list. Both need a small change: the harness needs group cases, and the codes test lists every code.
- A group expression that reads a host input (`currentUser`, allowed by P1) is refused with `compile.notSql`. The card's options have no input values.
