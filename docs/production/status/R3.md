# R3 Ports: data, host functions and inputs, clock, events, write

Status: done
Date: 2026-10-03
Branch / PR: sema/affectionate-gauss-ffttcx (pull request: see the branch)

## Done
Everything a program needs from outside now goes through a typed port. The host also declares typed inputs and functions at `createMinab`, and the checker, the interpreter and the compiler use them.

- `src/runtime/ports.ts` (new): `DataPort`, `WritePort` and `WriteTransaction` (interface only), `HostFunctions`, `ClockPort` (with `SYSTEM_CLOCK`), `EventSink` and `MinabEvent`, `PortError`, and `REFUSING_WRITE_PORT` (code `eval.writesNotSupported`).
- `src/language/host-declarations.ts` (new): `createMinab({ functions, inputs })` declarations, type words (`TEXT`, `TEXT?`, `TEXT[]`), and the checks of names (D10: a lowercase letter, D11: not a table name). A bad name or type throws `HostDeclarationError` at `createMinab`. A record input becomes a made-up table `@name`, so `currentUser.id` is typed like a column.
- Checker: a bare name can be a host input. A call can be a host function (same argument rules as a user `fn`). Validator: `scope.nameIsHostName` (an `fn`, `let` or parameter with a host name, D11) and `scope.assignToInput`. Both codes are in the registry and in `docs/reference/diagnostics.md`.
- Interpreter: host inputs come from `run({ hostInputs })`; a missing one is `eval.missingInput`. Host functions are awaited with the `AbortSignal`; no implementation is `eval.hostFunctionMissing`. A host input in a query is bound as a parameter.
- Compiler: a host function call is refused with `compile.hostFunctionInSql` (`CompileResult` error code), so it never goes into SQL.
- Clock: read once for each run and kept in the evaluation context (L6 uses it). Default: system clock, `UTC`.
- Events: one `EventSink`. The `statement` event goes out just before each data call, with the source range of the compiled node. A `timing` event follows each data call (`phase: 'data'`) and ends the run (`phase: 'run'`). A throwing sink is dropped.
- Data port: `DataPort.execute(query, { signal })` is the runtime type. `QueryExecutor` stays, and a one-argument executor still fits it.
- `MinabSchema.functions`, `MinabFunctionSchema` and `SchemaProvider.getFunction` are removed. A host config with `schema.functions` gets a clear error.
- Service cache key now includes the host declarations.
- Spec §8.7 "Host functions and host inputs" and showcase §15 (D27 example). Both are parse-tested (`parseOnly`, because the spec fixture schema declares no host names); `test/ports.test.ts` checks the behavior.
- Tests: `test/ports.test.ts` (37 tests). The tests that had `functions: []` in their schema lost that line.

## Questions for the owner
- **Option names.** The card says `functions` and `inputs` at `createMinab`; ADR 0002 says `hostFunctions` and `hostInputs`. I followed the card. The run side keeps the ADR names (`RunPorts.hostFunctions`, `RunInputs.hostInputs`). Recommendation: keep it, and fix the ADR text when R6 or G1 touches it.
- **Statement event and duration.** The card lists `durationMs` in the `statement` event, and also says it is emitted just before the data call. Both cannot hold. I kept the order (the playground's execution map relies on it) and moved the duration to a `timing` event after the call (`phase: 'data'`). Recommendation: keep it.
- Size: about 14 hand-written source files and about 900 changed lines with the tests (card budget 12 files, 1,000 lines). Many of the files are small edits (types, codes, schema). Within twice the budget.

## Later
- A bare unknown name (for example `currentUser + 1` when nothing declares `currentUser`) gets no diagnostic from `prepare`; it fails only at run time with `unknown name`. This was already so before R3 (the type checker reports `scope.unknownName`, the validator does not report it for a bare name). A host input that the host forgot to declare is the likely case — lane C (correctness) or L1 follow-up.
- A host name that is also a language keyword (`from`, `loop`) cannot be used in a program. `createMinab` does not refuse it yet — small check against the grammar's keywords — lane R, R4.
- The runtime does not check the argument values and the result type of a host function (`eval.hostFunctionResult`, ADR 0002 4.3) — needs the structured errors of R4 — R4.
- `EvalContext.onStatement` (with the AST node) stays for the playground's trace. Remove it when R8 moves the playground to `events` — R8.
- `INSERT`, `UPDATE` and `DELETE` do not use the write port yet — X5.
- The `local` flag of a host function is stored, not used — analysis tier (R5).
