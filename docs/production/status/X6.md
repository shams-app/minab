## Done
The last constructs of the language run. `INSERT`, `UPDATE` and `DELETE` work on a `JSON` array column, and assignment through a record path works, with `!` (create the missing record) and `|=` (merge). All eleven examples run, and no "not executed yet" refusal is left in the source.

- **`JSON` arrays** (`src/language/minab-json-writes.ts`, `minab-interpreter.ts` `jsonArrayWrite`): the column is read through the run's transaction, changed in memory and written back with one `UPDATE` of that column through the write port. `INSERT` adds one element (a list adds each element; a `null` column starts an array). `DELETE` and `UPDATE` choose elements with `[n]`, `[i]`, `[filter]`, `WHERE` (`.$index` works), `ORDERBY`, `LIMIT` and `OFFSET`. If nothing is chosen, nothing is written. `UPDATE` needs object elements (`:` `+:` `-:` `*:` `/:` `:|`). The column can sit behind a ref (`.doctor.meta`) or start at a loop variable (`c.tags`). In a dry run the run remembers the value it "wrote", so a second write to the same column starts from the first.
- **Path assignment** (`MinabSqlCompiler.compilePathAssign`, `minab-interpreter.ts` `assignPath`): `.doctor.id = 21;` is one `UPDATE` of the rows the path ends at; a `null` step is a no-op. A `!` step costs two statements: a check ("is the link empty?") and, if so, one statement that creates the row (`INSERT … DEFAULT VALUES` in a CTE) and links it. `|=` on a relation merges an object into the related row (creating it) and `= { … }` on a relation does the same. A filtered to-many step is one `UPDATE … WHERE`. `=`, `+=`, `-=`, `*=`, `/=`, `?=` and `|=` work on a column. A path may start at `.`, `^` or a loop variable over a table. The value is evaluated by the program first and bound as a parameter.
- **Errors**: `eval.cannotCreateRecord` (table and column) when a `!` row cannot be created (SQLSTATE 23502); `compile.writePath` for a path that cannot be assigned (for example a relation step after a to-many step). The run rolls back in both cases.
- **Dry run**: checks still read. After a created row, the next steps are listed only while they have a `!`, because a new row has no links yet.
- **Checker** (`minab-validator.ts`): a `JSON` column is a valid write target (an `INSERT` target cannot have a position or filter); the column of a to-many path takes one value (not a list); `|=` and `= { … }` on a relation check the object keys against the table.
- **Playground**: nothing was left in `CHECK_ONLY` (X5 emptied it). Cheat sheet: new entries for JSON array writes and path assignment, and the writes intro no longer says "not executed yet". New gallery example `path-assignment` (dry run on the demo data).

## Questions for the owner
