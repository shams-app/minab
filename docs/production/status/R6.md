## Done
A versioned JSON format for "run these programs with these inputs" and its answer now exists, with exact value encoding. The server (H2) and the browser client (H5) can be built against it at the same time.

- `src/runtime/wire.ts`: request and response types, `parseRequest`, `parseResponse`, `encodeValue`, `decodeValue`, `wireScalar`, `wireErrorResponse`, `WireError`. Exported from `src/runtime/index.ts`.
- `schemas/wire-v1.request.json`, `schemas/wire-v1.response.json` (+ `schemas/README.md`). They are in the package `files`.
- `docs/reference/wire-format.md`: the format, the encoding table and the codes.
- Five new codes: `wire.invalidRequest`, `wire.invalidResponse`, `wire.invalidValue`, `wire.tooManyRuns`, `wire.unsupportedVersion`. The generated `docs/reference/diagnostics.md` has a new `wire` area.
- `test/wire.test.ts`: round trip of every type, the card's rejections, the schema checks.
- `changes/R6.md`.

Notes on choices:
- The card and ADR 0002 section 9 differ. I followed the card: `program: { ref: { id, version } } | { source }`, and `inputs`, `record`, `fieldValue` at run level (`inputs` = host inputs). The ADR has `programId`, `version` and `inputs.record`. ADR section 9 should be updated to match (owner).
- Decimals leave in the shortest exact form (`"24.9"`, not `"24.90"`). The value is exact; trailing zeros are not kept (same as `externalize`).
- A `DATETIME` is a `Date` in the interpreter and `"...Z"` on the wire. Offsets are refused. L6 is not merged, so I used D21's text.
- `source` is refused unless `parseRequest(json, { allowSource: true })` (D34). Both `ref` and `source` together is refused.
- Extra rules in `parseRequest`: `runs` needs at least one run, and ids must be unique.
- Errors never hold the wrong value, only its path.
- Request-level errors use `{ v: 1, error }`; `parseResponse` accepts it.
- Small edits outside the card's file list, needed by the registry: `scripts/diagnostics-doc.mjs` (the `wire` area text), `test/diagnostic-codes.test.ts` (area regex, five `runtime` entries), `package.json` `files` (adds `schemas`), `src/runtime/README.md`.
- The JSON Schema is checked by a small checker inside the test (no new dependency, D09). The schema has no `maxItems` on `runs`, because the limit is the host's.
