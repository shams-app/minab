# L1 Call functions by name: remove `&`

Status: done
Date: 2026-10-02
Branch / PR: sema/affectionate-meitner-4ap1ga

## Done
A user function is now called `name(...)`, like a built-in, and `&` is gone from the grammar, the checks, the interpreter, the examples, the spec, the showcase and the playground. D10 (case rule) and D11 (no name reuse) are enforced.

- **Grammar.** `FunctionCall` and its `Primary` alternative are deleted. `langium generate` prints no warning. The TextMate grammar is regenerated.
- **Type checker.** `inferCallExpression` looks up a built-in first, then a declared `fn` (new `inferUserCall`, which replaces `inferFunctionCall`). A name that is neither gives `call.unknownFunction` (`unknown function "foo"`). The callee `NameRef` is still never inferred on its own.
- **Validator.** `FunctionCall` is no longer registered. New codes: `call.functionNameCase` (a `fn` name needs a lowercase letter), `scope.nameIsFunction` (a `let` or a parameter has a function's name), `scope.functionNameIsTable` (a `fn` has a table's name). Removed codes: `call.ampersandOnBuiltin`, `call.missingAmpersand`, `call.reservedName` (replaced by the case rule), `call.unknownUserFunction` (merged into `call.unknownFunction`). The registry stays sorted. `docs/reference/diagnostics.md` is regenerated.
- **Interpreter.** `builtin()` sends a name that is not a built-in to `callFunction`. Messages no longer mention `&`.
- **SQL compiler.** A user function call still refuses to compile. The reason now names the function. The SQL never contains `discounted(`.
- **Tests.** Call sites updated. The old item 10 tests are rewritten (a bare user call passes, D10 and D11 are enforced, an unknown name gets `call.unknownFunction`, `&foo(1)` is a syntax error). New `test/function-names.test.ts` adds a test-only built-in `LOWER` (a mock of the built-in table) and shows that `fn lower(...)` still checks and runs. New `test/no-ampersand-calls.test.ts` is the drift guard.
- **Examples, spec, showcase, rules.** Two examples. Spec §5.3 (new D10/D11 paragraph), §8 preamble and §8.4, §11 grammar block, §12 item 10 ("Resolved, then revised 2026-09-24", old text kept as history). Showcase. The two lines in `.cursor/rules/`.
- **Playground.** Tokenizer: `&` is no longer a token; a name before `(` that is not a built-in is the new token `function` (CSS variable `--syntax-function`, replaces `--syntax-sigil-call`). Monaco: no `&` trigger. Hover shows the signature of a called function; user functions are offered next to built-ins in completion. Landing page: the sigil grid has 5 cards. Tour lesson 10, cheat sheet, gallery, `design/*.md` updated.

Differences from the card, noted here:
- The drift guard scans fenced code blocks of the spec and showcase, so the history text of §12 item 10 (plain prose) needs no marker. No exact marker was needed.
- `grep -rE '&[A-Za-z_]+\('` still finds the drift guard itself and the tests that check `&foo(1)` is rejected (`test/typechecking.test.ts`, `test/no-ampersand-calls.test.ts`, `playground/test/tokens.test.ts`), plus spec §12 item 10 history. None is a call in a program.
- The playground `sigil.call` token was replaced by `function`, not only deleted, so user function names keep a color. (Small playground addition, not a language change.)
