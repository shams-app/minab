## Done
All three loop forms run, with `break` and `continue` (labels too). `.$index` works on arrays. Tuples run. `overdue-loop` runs and answers `true`. Only `INSERT`, `UPDATE` and `DELETE` are still check-only.

- `src/language/minab-interpreter.ts`: `loop` (range with `by` or `where`, for-in with `where`, bare condition). `break` and `continue` travel as a thrown `LoopSignal`; a loop catches the ones that name it (or have no label). Every step, also a skipped one, calls `RunBudget.countIteration` (`limit.tooManyIterations`). A loop's tail value is dropped.
- A for-in loop over a table collection reads its rows with one statement (`MinabSqlCompiler.compileRows`, new), then loops in memory. The row limit applies.
- `.$index` is zero-based (spec §3.5). It is set for array filters and array loops. On table rows it fails with the new code `eval.indexNeedsArray`.
- Tuples: a tuple literal is an array; `t[n]` reads a position (it already did). The first item of a tuple shares its syntax node with the tuple, so the number-literal reader now drops a leading `(`.
- Playground: loops, `.$index` and tuples are no longer check-only (`program.ts`); gallery (`overdue-loop`, `tuples`, `reconcile-overdue-accounts`), cheat sheet, tour lesson 12 and README updated.
- Examples: `overdue-loop` is now a `run` example (config has a record and rows). `reconcile-overdue-accounts` stays check-only; its config now has data, so the loop runs and stops at the first `UPDATE`.
- Tests: `test/loops.test.ts` (new, 20 cases).
