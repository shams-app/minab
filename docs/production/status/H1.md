## Done
`@shamsine/minab/node` now has the Node adapters, and the package loads from ES modules, CommonJS, Jest and Bun.

- `src/node/query-function.ts` (new): `queryFunctionDataPort((text, params) => rows)` for TypeORM and Prisma. It takes an array or `{ rows }`. A failure keeps its SQLSTATE.
- `src/node/clock.ts` (new): `systemClock(timeZone?)`. A wrong zone name throws at once.
- `src/node/pg.ts`: `pgDataPort` now shares the error wrapper with the query-function port.
- `src/node/README.md`: use, `$1` placeholders, the request's transaction, Node versions.
- `scripts/build-cjs.mjs` (new): esbuild bundles `.`, `./node`, `./nestjs` to `out/cjs/*.cjs`. Langium is inside. `pg`, `@nestjs/*`, `rxjs`, `reflect-metadata` stay outside. `npm run build`, `build:cjs` and `build:release` run it.
- `package.json`: `require` targets in `exports`, `out/cjs` in `files`, `esbuild` dev dependency (D09), `test:consumers` script. `bun.lock` and `package-lock.json` updated.
- `test/consumers/` (new, with README) and `.github/workflows/consumers.yml` (new, Node 22 and 24, Bun): five consumers: ESM, CommonJS, Jest (default config), Bun, TypeScript with `moduleResolution: node`. Each installs the packed tarball.
- `test/node-adapters.test.ts` (new): 10 tests (fake query function, `{ rows }`, error code, clock, correlated rule through `pgDataPort`, transaction insert then rollback, coded database error).
- `tsconfig.json`: excludes `test/consumers` (its self-import of the package made `tsc` fail with TS2209).

## Later
- The `.d.ts` files import `langium`, which old `moduleResolution: node` cannot resolve. The TypeScript consumer needs `skipLibCheck: true` (the default of `nest new`). Hiding Langium types from the public `.d.ts` would fix it — owner to decide — Q-lane or R lane.
- Each CommonJS bundle is self-contained, so a class such as `PortError` in `.` is not the same object as in `./node`. Hosts should match errors by `code`. Making `./node` share the runtime bundle would remove this — can wait — H2 lane.
