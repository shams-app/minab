## Done
All four Build steps are done, each with a test that fails without its fix. The guides and `docs/security.md` now say what the code does.

- **Guards with `forRootAsync`** (`src/nestjs/module.ts`). `MinabModuleAsyncOptions` has `guards` next to `endpointPath`. They go on the run controller. If the factory returns `endpoint.guards` or `endpoint.path`, the module provider throws at startup with a message that names the fix ("Move them to `guards` in the forRootAsync options, next to `endpointPath`"). `guards` without `endpointPath` throws at once, because the guards would guard nothing. `forRoot` is unchanged.
- **One runtime per schema** (`src/nestjs/service.ts`). The runtime cache key is `[version, sha256(JSON of the schema)]`. The hash is kept in a `WeakMap` keyed by the schema object, so a loader that returns the same object hashes it only once. Prepared programs are keyed by the same schema key. Cost, measured with a big schema (100 tables × 40 columns, 0.5 MB of JSON): about 2–3 ms for the first hash of an object, about 0.2 µs after that. That is inside Q4's budgets (warm prepare ≤ 5 ms).
- **Keyword host names** (`src/language/host-declarations.ts`). `keywordsOfGrammar()` walks the generated grammar (`MinabGrammar()`) for its word keywords. It uses no hand-written list. `createMinab` throws a `HostDeclarationError` for a host input or host function with such a name: `host input "from": this is a keyword of the language, ...`.
- **Host function results** (`checkHostResult` in `host-declarations.ts`, called in `callHostFunction` in `minab-interpreter.ts`). Each result is checked against the declared type: the base type, and `null` only with a `?` (for a list: the list and each item; `undefined` counts as `null`). A wrong result is the run error `eval.hostFunctionResult` with `name` and `expected` (new code in `codes.ts`; `docs/reference/diagnostics.md` regenerated). Accepted forms: INTEGER is a safe whole number or a `bigint`. DECIMAL is a finite number, a `Big`, number text or a `bigint` (text and `bigint` become a `Big`; a number stays a number, as before). DATE, TIME and DATETIME are what the date readers accept (DATETIME is normalized). UUID is UUID text. JSON is any value.
- **Docs**: `docs/guides/embedding.md` (§3 shows `endpointPath` and `guards` together, plus the cache key, keyword names and result check), `docs/guides/shamsine.md` (the server module now has `endpointPath` and `guards` next to the factory; the `version` notes), `docs/security.md` (points 2, 6, 11, 12 and the checklist), `src/nestjs/README.md`, `src/runtime/README.md`, `test/nestjs/README.md`.
- **Tests**: `test/nestjs/host-safety.test.ts` (new; the 403 test runs the handler through Nest's guard pipeline, `ExternalContextCreator`, with no HTTP adapter: `@nestjs/platform-express` is not a dependency of the root package. A first version used a real HTTP server and failed in CI on Node 24, where that package is not installed), `test/ports.test.ts` (keyword names, host function results), `test/diagnostic-codes.test.ts` (registry entry for the new code).
