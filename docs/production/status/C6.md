# C6 `check` accepts a top-level collection filter

Status: done
Date: 2026-10-02
Branch / PR: sema/admiring-hawking-cub757

## Done
A rule like `COUNT(.orders[.status == "cancelled"]) < 5` now passes `check` and runs. The scope resolver knows the rule's `recordTable`, so a top-level `.` (and `^`) has a table. The examples and gallery that worked around the bug are back in their natural form.

- **Resolver.** `MinabScopeResolver` takes the `MinabRuleContext` (new second constructor argument, wired in `minab-module.ts`). The root scope level gets `recordTable` as its table, when the schema has that table. Without `recordTable` nothing changes: the error is the same as before.
- **Tests.** New `test/collection-filter.test.ts` runs the real validator and checker: the showcase §1 rule, a nested filter, `.customer.orders[...]`, a field rule with `$` next to a filter, a wrong column inside a filter, and no `recordTable`. New CLI tests in `test/cli.test.ts`: `check` is clean, `run` gives `true`, and `check` without `rule.recordTable` still fails.
- **Examples.** `examples/cancelled-orders-limit` is the bare rule again, with `rule`, `record` and a fixture in its config. `expected.json` is now a `run` result `true`, 1 statement (one scalar `COUNT` subquery, as expected), `compiles: false`. `examples/overdue-loop` loops over `.orders` (still check-only) and its config has `rule.recordTable`.
- **Playground gallery.** The `COUNT(#Order[.customer == ^ …])` entry now uses `COUNT(.orders[...])`. The repo example `cancelled-orders-limit` is a rule now, so its gallery entry became the rule with Donald and Ada presets. It replaces the separate `cancellation-limit` entry, which had become the same program (so the gallery has one entry less). The `overdue-loop` gallery host got `rule.recordTable`.
- **Fragment.** `changes/C6.md` (`type: fixed`).

- The card's nested example `.orders[.items[.qty > 2]]` is not a valid filter: the inner filter is a collection, not a BOOLEAN, and the type checker (rightly) rejects it. The test uses `.orders[EXISTS(.items[.qty > 2])]`.
