## Done
The three release scripts, the two workflows and the release guide are written and tested. The scripts are tested, and both workflows have run.

- `scripts/changelog.mjs` (`--version`, `--check`, `--notes`, `--root`), `scripts/bump-version.mjs`, `scripts/next-version.mjs`, each with a `.d.mts` file for the tests.
- `.github/workflows/release.yml`: on a `v*` tag and on manual run with `dry-run`. Checks the tag, builds, tests with Postgres, builds the `.vsix` and runs `check:vsix`, publishes to npm, creates the GitHub release, publishes to the Marketplace and Open VSX. A missing `VSCE_PAT` or `OVSX_PAT` prints "skipped: secret ... not set".
- `.github/workflows/next.yml` (D05 = yes): on push to `main`, not for `docs/**`, `playground/**` or `**/*.md`. Publishes `X.Y.Z-next.N` with the npm tag `next`. The version is set in CI only.
- `.github/workflows/plan.yml`: one new step, `changelog.mjs --check`.
- `docs/releasing.md`: the checklist, the one-time setup and the `next` channel.
- `test/release-scripts.test.ts`: 18 tests on temporary folders.
- `changes/Q2.md`. `scripts/README.md` lists the new files.

Small differences from the card:

- The `.vsix` is built and checked **before** `npm publish`, so a broken extension stops the release before anything is published.
- `release.yml` publishes a prerelease version (for example `1.0.0-rc.1`) with `--tag next` and marks the GitHub release as a prerelease. npm needs this.
- The `paths-ignore` in `next.yml` uses `**/*.md` (all Markdown files), not only `*.md` at the root.
- `npm install -g npm@^11.5.1` runs first, because trusted publishing needs that npm version.
- The extension changelog gets "No change for the extension in this release." when no fragment is for it, so the version test stays green.
