## Done
`minab check`, `compile` and `run` now use `createMinab`, `prepare`, `compile()` and `run()`. The CLI no longer builds Langium services. The Postgres code moved to `src/node/pg.ts`.

- `src/cli/main.ts`: config, `createMinab`, `prepare`, then diagnostics, `compile()` or `run()`. `--trace` prints `statement` events to stderr. Human output is the same as before (I compared the output of check, compile, run and `--trace` before and after).
- `src/node/pg.ts` (new): `pgDataPort(client)` is a `DataPort`. `connectPostgres(url)` loads `pg` from the host and connects. A database error keeps its SQLSTATE. Both are exported from `src/node/index.ts`. The `notReady` stub export is gone from that file. The folder README is updated.
- `src/cli/executors.ts`: re-exports the fixture executor, `traced`, `pgDataPort` and `connectPostgres`. `PostgresExecutor.connect(url)` still works.
- `src/cli/diagnostics.ts`: new `toCliDiagnostic` turns a runtime diagnostic into the shape the CLI prints. The other functions are unchanged.
- `minab run --json` on a failed run prints `{ "ok": false, "error": { code, message, params, range? } }` on stdout. The human message on stderr is the same as before.
- The runtime hides driver text on purpose. So the CLI keeps the first `DataSourceError` of a run and prints it as before (`minab: <message>`, exit 1).
- `test/cli-imports.test.ts` (new): `src/cli/` imports only `src/cli/`, `src/runtime/`, `src/host/`, `src/node/`, and never `langium`.
- `test/cli.test.ts`: one new test (`code` in JSON). No existing assertion changed.
