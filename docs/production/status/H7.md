# H7 The playground uses the published browser entry

Status: done
Date: 2026-10-04

## Done
The playground's worker and client now run on the browser entry: `serveMinab` in the worker and `createWorkerMinab` on the UI thread. The first try of this phase stopped (the engine is not a thin wrapper), the owner changed the card on 2026-10-04, and this is the work of the new card. The engine keeps what only the playground needs (trace, demo Postgres, SQL console, editor intelligence). It is served as one host request.

- `src/browser/`: host requests (`serveMinab({ requests })`, `WorkerMinab.request(name, payload, { signal })`), host events (`server.emit`, `WorkerMinab.onEvent`), and one server for each endpoint (a second `serveMinab` on an endpoint replaces the first; before, a worker file that imported the worker entry ran two servers). New code `wire.requestFailed`. The bridge stays version 1.
- `playground/src/engine/worker.ts`: `serveEngine(endpoint)` (also used by tests). `protocol.ts`: the old request, response and event message types are gone; `ENGINE_REQUEST` and `ENGINE_STATUS_EVENT` replace them.
- `playground/src/client/engine-client.ts`: a thin layer over `createWorkerMinab`. `call`, `onStatus`, `restart` work as before. In-flight calls fail with "the engine was restarted". New `run(source, id, signal)`.
- A run that is replaced is now stopped: the controller aborts it, the engine passes the signal to the program, and a run aborted while it waits for the database never starts.
- Tests: `test/browser/requests.test.ts` (10), `playground/test/engine-client.test.ts` (7). Docs: `src/browser/README.md`, `playground/README.md`, `docs/reference/diagnostics.md` (generated). Fragments: `changes/H7.md`, `changes/H7-2.md`.
