# C4 Text `+`, division and `%`

Status: done
Date: 2026-10-03
Branch / PR: claude/phase-c4-production-h7gr7b

## Done
Text `+`, `/` and `%` now give the same answer in the interpreter and in the compiled SQL (D13 option a, D14).

- **Text `+`.** The checker accepts two texts (`TEXT` or `CITEXT`, also `text + null`), result `TEXT`, nullable if a side is. Text with a number is the existing error `type.arithmeticNeedsNumeric`; its message now says "use CAST". The interpreter joins texts (`null` side gives `null`). The compiler emits `||`. The compiler now gets the type checker, to tell text `+` from number `+`.
- **`/`.** The checker types `/` as `DECIMAL`. The interpreter divides with `big.js` (16 places, half away from zero). The SQL form is `sign(a) * sign(b) * div(div(abs(a) * 2e16, abs(b)) + 1, 2) * 1e-16` on `numeric` operands. It is exact: no Postgres division, so the scale never drops below 16, and no double rounding.
- **`%`.** Pinned: sign of the left side, also for `DECIMAL`.
- **By zero.** New code `eval.divisionByZero`. Postgres `22012` has the same message and counts as the same error in the harness.
- **Tests.** `test/differential/cases/c4-operators.cases.ts` (24 cases, both runtimes), text `+` and `/` type rules in `test/typechecking.test.ts`, the new code in `test/diagnostic-codes.test.ts`. The two C4 known gaps are removed. The harness test that used a C4 gap now uses a C5 gap.
- **Docs.** Spec §5.1 has the operator table. Showcase §7 has one example each. `docs/reference/diagnostics.md` is regenerated.
