# L5 Built-ins with several arguments: text, null and number functions

Status: done
Date: 2026-10-03
Branch / PR: sema/fervent-albattani-dy62y8

## Done
Built-ins are now one table that the checker, the interpreter and the SQL compiler read. The table gives each built-in its kind, its parameters (a type rule, optional, or rest), a return-type rule, the interpreter function and the SQL form. The eight old built-ins moved into it with no change in behavior, and no `switch` on a function name is left. The 16 functions of D20 are added and give the same answer in both runtimes.

- **Table.** `src/language/minab-builtins.ts`: `BuiltinSignature`, `checkBuiltin` (count, then each type, then rules across arguments), `BuiltinError`. Aggregates and predicates keep their old codes. Scalars use `call.wrongArgumentCount` (new) and `call.argumentType`.
- **Checker.** `inferCallExpression` infers all arguments and calls `checkBuiltin`. The grouped-aggregate promotion still works for one-argument aggregates.
- **Interpreter.** `builtin()` runs aggregates over items and scalars over values. A `null` argument gives `null` unless the entry sets `nullPropagates: false` (`COALESCE`, `GREATEST`, `LEAST`). `CITEXT` is read from the inferred type.
- **SQL compiler.** `scalarCall` uses the entry's `sql` form. The compiler now gets the type checker (to see `CITEXT`). `STARTS_WITH`/`ENDS_WITH`/`CONTAINS` use `starts_with`, `reverse` and `strpos`, so `%` and `_` are plain characters. `TRIM` uses `btrim(x, E' \t\r\n')`.
- **Fix found on the way.** A negative literal (`-2`) compiled to `-$1`, which Postgres refuses. It now binds as one number (`changes/L5-2.md`). `ROUND(.x, -2)` and `SUBSTRING(.s, -5)` need it. Cases `ROUND with a negative digits count` and `SUBSTRING start below 1 without length gives all` fail without it (I checked).
- **Tests.** `test/differential/cases/l5-text|null|number.cases.ts` (109 cases: null, empty text, Persian, emoji, negative numbers, half values, `CITEXT`). New `test/builtins.test.ts` (38 tests: arity, argument types, result types, table shape). New code row in `test/diagnostic-codes.test.ts`. `test/function-names.test.ts` no longer mocks `LOWER`: the real one is used (the old mock had no `params` and made the checker throw). Three showcase blocks added to `PIECES` in `test/spec-examples.test.ts`.
- **Docs.** Spec §5.3.1 split into "Aggregates and predicates" and "Scalar functions", with the null rule and the known case difference below. Showcase section 16. `docs/reference/diagnostics.md` regenerated.
- **Playground.** Hover docs and completion (`intel.ts`), highlight names (`tokens.ts`), four cheat sheet entries.

Differences from the card, noted here:
- `COALESCE` is not nullable when **any** argument is not nullable (D20 says "if the last argument"). The longer rule is also correct, and it includes the D20 case.
- `call.builtinArity` stays for aggregates and predicates (an existing test uses it). Scalars use `call.wrongArgumentCount`.
- The SQL compiler uses the type checker (already added to it on `main`) to see `CITEXT`.
