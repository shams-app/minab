## Done
`@shamsine/minab/nestjs` is now the real NestJS integration. A Nest app adds `MinabModule` and gets `MinabService`, an exception filter, a logger adapter and an optional run endpoint for stored programs.

- `src/nestjs/` (new files, with README): `module.ts` (`forRoot`, `forRootAsync`), `service.ts` (`prepare`, `run`, `runStored`, plus `loadStored` and `loadSource`), `exception.ts` (`MinabException`, `minabHttpStatus`), `filter.ts`, `logger.ts`, `controller.ts`, `options.ts`. It replaces the R2 stub.
- Schema for each request: `schemaLoader(context)` runs for every request. One runtime is kept for each schema `version`. Prepared programs are cached by schema version, program id and program version (D34).
- Filter: check failures and `limit.*` give 422 (with the diagnostics, codes and ranges), `cancelled` gives 499, `wire.*` gives 400, an unknown program gives 404, `data.*` gives 500 without SQL, driver message or stack.
- Logger: off by default when `NODE_ENV=production` (D37). When on: 100 entries for each run (D36), one line for each value (newlines, control characters and `\` escaped), tagged with program id and request id. Statement lines are opt-in, at debug level, with the SQL text but never the parameter values.
- Run endpoint (only when `endpoint` is set): `POST <path>` (default `minab/run`) with a wire v1 request. It runs stored programs. `program.source` is refused unless `endpoint.allowSource: true`. It refuses more runs than the `batchRuns` limit. The ports, the schema and (optionally) host inputs come from the server. `endpoint.guards` puts the host's guards on the route. A valid request is 200, and each result has its own `ok`.
- New registry code `wire.programNotFound` (404) with its test entry and `docs/reference/diagnostics.md` regenerated.
- `tsconfig.nestjs.json` (decorator options) and `tsconfig.nestjs.build.json`. The root `tsconfig.json` and `tsconfig.build.json` leave `src/nestjs` out. `build` and `build:release` run `tsc -p` for it after the root build. `vitest.config.ts` turns on legacy decorators. `scripts/build-cjs.mjs` passes the same setting to esbuild.
- Dev dependencies (D09): `@nestjs/common`, `@nestjs/core`, `@nestjs/testing`, `rxjs`, `reflect-metadata`. `package-lock.json` and `bun.lock` updated. The optional peers were already in `package.json` (R2).
- Tests: `test/nestjs/` (new, with README): 51 tests. Consumer `test/consumers/nest-cjs/` boots a module from the packed package with NestJS 11 (CommonJS). `consumers.yml` already runs every consumer, so it needed no change.

## Later
- The endpoint does not cancel runs when the client closes the connection (`cancelled` / 499 exists, but nothing wires the socket to the run's `AbortSignal`) — it needs a platform-specific hook — H3 (example app) or a later H lane card.
- The endpoint has no hook to release a per-request transaction after the batch — the host's `ports` function can open it, but cannot close it — H3 will show whether this is needed.
- `StoredProgram.schemaVersion` (ADR 0002 section 4.6) is not used: the cache key uses the schema version from the loader — add it with Q5 (`languageVersion`).
- The controller imports the value helpers (`decodeInputs`, `encodeBy`, `resultWireType`) from `src/browser/protocol.ts`. They have no browser code, but they would fit better in `src/runtime/` — a small move, with the worker — H5.
