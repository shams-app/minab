## Done
Three sweeps are finished. Every checker diagnostic has a stable code and parameters. The code base is formatted once and linted with OXC in CI. Each example keeps its expected result in its own file.

- **Codes.** `src/language/diagnostics/codes.ts` is the registry: 72 entries, sorted by code, each with severity, the English message built from parameters, and one sentence of explanation. Messages are word for word as before, with the exceptions listed below. The validator, the type checker, the scope resolver and the built-in checks use it. Lexer and parser errors get `syntax.lexer` and `syntax.parser` in one place (`src/language/diagnostics/minab-document-validator.ts`). The code is in the LSP `code` field and the parameters are in `data.params`.
- **Where tools read it.** `minab check --json` prints the code and parameters. The playground's `EngineDiagnostic` has an optional `code` (no UI change).
- **Reference page.** `scripts/diagnostics-doc.mjs` writes `docs/reference/diagnostics.md` (`npm run docs:diagnostics`). `test/diagnostic-codes.test.ts` fails when it is out of date.
- **Format and lint (D08, D09): OXC works, so it is used.** `oxlint` with `oxlint-tsgolint` runs the type-aware rules `no-floating-promises`, `no-misused-promises` and `await-thenable`, plus `no-unused-vars` and `consistent-type-imports`, with this repo's TypeScript 5.9. `oxfmt` keeps today's style (4 spaces, single quotes, semicolons, no trailing commas, arrow parens avoided) with `printWidth` 160, which gave the smallest diff of 120, 140 and 160 (28 files in the root, +235 −259 lines). Config: `.oxlintrc.json`, `.oxfmtrc.json`. Scripts: `lint`, `format`, `format:check` in the root; `format`, `format:check` in `playground/`. `npm run lint` first runs `langium:generate` (script `prelint`), because the type-aware rules need the generated types. New workflow `.github/workflows/lint.yml`.
- **One-time format.** Commit `c222485` (`chore: format with oxfmt`) holds only formatting. Its hash is in `.git-blame-ignore-revs`.
- **Lint findings.** One: an unused parameter `ctx` in `aggregateOverSource` (`minab-sql-compiler.ts`). Removed. No real bug was found, so there is no new bug test.
- **Examples.** `examples/<name>/expected.json` for all 11 examples. `test/examples.test.ts` reads them. A folder that holds `<name>.minab` and has no `expected.json` fails the test. Folders without such a program are ignored. Rules are in the new `examples/README.md`.

Differences from the card, noted here:
- **Lint of `vscode-extension/src` is not type-aware.** `oxlint-tsgolint` rejects the extension's tsconfig (`moduleResolution=node10` was removed in the TypeScript version it uses). So `npm run lint` runs the type-aware rules on `src`, `test` and `scripts`, and the non-type-aware rules on `vscode-extension/src`. The playground has no linter (W2).
- **`minab check --json` with errors.** The card says `check --json` prints the code for a type error. Before, with errors it printed only the human text on stderr and nothing on stdout. It now also prints `{ "ok": false, "diagnostics": [...] }` on stdout. The stderr text and the exit code are unchanged. Fragment `changes/B1-2.md`.
- **Messages that are not word for word.** (1) The type checker's internal text for `$` outside a field rule is now the validator's longer text (one code, `rule.fieldValueOutsideFieldRule`). The short text never reached a user. (2) A guard `KEY used outside GROUPBY` that cannot happen (the scope resolver already refused) now uses `scope.keyWithoutGroupBy`. 
- **Two codes for one idea in two places.** `scope.columnNeedsTable` (scope resolver, text ends with "requires the Phase 4 type system", asserted by `test/scoping.test.ts`) and `type.columnNeedsTable` (type checker) keep their different texts, so they are two codes.
- **Three guards the grammar cannot reach**, tested with a hand-made node or a stubbed scope stack, not with a program: `type.cannotInfer`, `type.unsupportedOperator`, `scope.noActiveScope`. (The registry has no other code without a program.) They protect against a later grammar change.
- **Size.** 17 hand-written files and about 1,275 changed lines, over the budget of 12 files and 1,000 lines but under twice the budget. About 430 lines are the registry's message and explanation text. All of it is needed for "Done when".
- **`bun.lock` and `playground/bun.lock`** are updated with `bun install --lockfile-only` (adds only the new dev dependencies), because D07 keeps both lockfiles.
