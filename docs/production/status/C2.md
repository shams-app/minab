# C2 Exact `DECIMAL` numbers

Status: done
Date: 2026-10-02
Branch / PR: sema/loving-maxwell-39rywy

## Done
`DECIMAL` values are exact in the interpreter (`big.js`), as `numeric` is in Postgres. `INTEGER` stays a JavaScript number and a result outside ±9,007,199,254,740,991 is the error `eval.integerOutOfRange`. A `DECIMAL` result leaves Minab as a string in its shortest exact form. A decimal parameter is bound to SQL as text.

- **Dependency.** `big.js` (runtime) and `@types/big.js` (dev). `package-lock.json` and `bun.lock` are updated.
- **`src/language/values.ts` (new).** Number helpers: literal reading, exact `+ - * / %`, comparison, range check, `normalizeIn` (values in), `externalize` (values out), `sqlParameter`.
- **Interpreter.** A literal with a `.` is a `Big`, read from its own text (so `0.30` and 20 digits are not rounded). `+ - *`, unary minus, `== != < <= > >=`, `IN`, `SUM`, `AVG`, `MIN`, `MAX` are exact. `/` and `%` accept `Big`. The record under validation, `$`, `let`, function parameters and return values are normalized by their declared type. A value that SQL computed is read by the static type of the expression (the interpreter now gets the type checker for this).
- **Values out.** `evaluate` turns every `Big` into a string. `formatValue` prints a decimal string without quotes. `--json` prints a JSON string. Numbers inside a `JSON` value stay JSON numbers.
- **SQL.** A decimal literal is bound as its own text. Any `Big` bound as a parameter is text.
- **Error code.** `eval.integerOutOfRange` is in the registry (new area `eval`). The code leads the error message until R4 makes errors structured. Docs page regenerated.
- **Seeds.** `src/host/ddl.ts` accepts decimal text for a `numeric` column, because a JSON number cannot hold 20 digits.
- **Tests.** `test/differential/cases/c2-decimal.cases.ts` (25 cases), `test/decimal.test.ts` (24 tests). The C2 known gap is gone. C1 decimal cases now expect strings. `test/support/minab.ts` compares a decimal string with a database `Decimal` by exact text.
- **Examples and playground.** `examples/discounted-total/expected.json` is now `"170"`. The playground gallery (two entries) and the tour goal of "functions" expect the decimal string.
- **Spec.** §7.2 has a new "Exact numbers" paragraph.

Differences from the card, noted here:
- **`"24.9"`, not `"24.90"`.** D17's example says `"24.90"`; the card and the "shortest form" rule say `"24.9"`. I followed the card.
- **Division by zero.** `INTEGER / 0` and `% 0` keep today's JavaScript result (C4 owns them). A decimal division by zero is an error.
- **No root `README.md` change.** Its output blocks did not change.

## Questions for the owner
- `formatValue` prints any top-level string that looks like a number (`"170"`) without quotes, because a decimal result is a string and the function cannot tell it from `TEXT`. A `TEXT` value `"170"` prints as `170` in the human output (not in `--json`). Recommendation: accept it for now; R6 (wire format) can add a type tag if it matters.
