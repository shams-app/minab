# P1 Group expressions: aggregates over the rows of a group

Status: done
Date: 2026-11-03
Branch / PR: hamcker/modest-johnson-auzfem

## Done
A host can now prepare a group expression: one expression over the rows of a group of one table, such as `SUM(.Revenue) - SUM(.Cost)`. It checks, gets editor help, and runs in the interpreter over `RunInputs.groupRows`. P2 will turn the same expression into SQL.

- `ruleContext.groupTable` (`src/language/schema.ts`). `rootTableOf()` gives the table a top-level `.` means. `prepare` throws for `groupTable` with `recordTable` or `isFieldRule`, or for a table that is not in the schema. `ProgramKind` has `'group-expression'`.
- Checker (`minab-type-checker.ts`): an aggregate takes a per-row expression (`SUM(.Price * .Units)`). `SUM`, `AVG`, `MIN` and `MAX` are nullable (empty group). `/`, `%` and `\` are nullable.
- Validator (`minab-validator.ts`, `checkGroupExpression`): new codes `aggregate.fieldOutsideAggregate`, `aggregate.nested` and `groupExpression.unsupported` (in the registry and `docs/reference/diagnostics.md`).
- Interpreter (`minab-interpreter.ts`): an aggregate reads its argument once for each row. A `null` is left out like SQL. An empty group gives `null` for `SUM`, `AVG`, `MIN`, `MAX` and `0` for `COUNT`. Division by zero gives `null` only when `groupRows` is set; every other program keeps `eval.divisionByZero`.
- Analysis: `groupColumns` and `aggregates` (first-use order). `tier` is `local`. `groupColumns` are also in `dependencies`.
- Editor: completion after `.` lists the group table's columns, numbers first inside an aggregate. Hover says "a column of the group".
- Docs: spec §4.2.1, Shamsine guide "Calculated values for a pivot", `src/runtime/README.md`, test READMEs, `changes/P1.md`.
- Playground: `ProgramKind` type and a status-bar label gain `group-expression` (needed to build).
- Tests: `test/group-expression.test.ts` (29), `test/editor/group-expression.test.ts` (4), `test/fuzz/group-expression.test.ts`, three cases in `test/diagnostic-codes.test.ts`. `test/spec-examples.test.ts` skips the §4.2.1 block (it needs `groupTable`).

Differences from the card:
- Host inputs: only `currentUser` is allowed. Any other declared input is `groupExpression.unsupported`, as agreed with the owner ("inputs" are refused).
- A call to a name that is no built-in and no host function is reported as `groupExpression.unsupported` ("the user function"). The checker also reports `call.unknownFunction` for it.
- A filter (`.tags[...]`) is also `groupExpression.unsupported`, because `.` inside it would mean an element, not a row.
