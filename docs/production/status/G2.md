Where the guide differs from the card (the code and the monorepo showed otherwise):

- **Tables need `sqlName`.** Dynodb names each Postgres table by the dataset **id** (`ds_…`), not by the name. The card said `sqlName` is not needed. It is not needed for user fields, but it is for tables and for the seven system columns (`created_at`, …). I found no code that renames them.
- **`id` is `INTEGER`, not `TEXT`.** `createTable` makes the primary key `INTEGER GENERATED ALWAYS AS IDENTITY` (or `SERIAL`). `createdBy`, `updatedBy`, `deletedBy` are `TEXT` (card: right).
- **`numberRange` and `timeline` are not `JSON`.** Their columns are `numrange` and `tstzrange`. They are marked unsupported. `week` is a `varchar(10)` text, not `JSON`.
- **`lookup` and `formula` are `JSON`**, because Dynodb caches them as `jsonb`, not "the type of what they compute". `rollup` is `DECIMAL`, `count` is `INTEGER`.
- **`url` as `JSON` does not work.** `url.tab` fails with `type.memberOnNonRecord`. The guide says to declare `url` as a typed record per page.
- **Messages use "field" and "dataset"** (words from `translations.json`), not "column" and "table".

## Questions for the owner
- **System columns.** Is it true that `createdAt` is stored in `created_at` (the code of `createTable` says so, and the system fields are named `createdAt`)? Recommendation: check one real application database before M.5, and keep `sqlName` in `toMinabSchema` for the seven system fields.
- **`id` type.** `dynodb.constants.ts` says `uuid`, `createTable` makes `INTEGER`. Recommendation: check a real database, then fix the constant or the guide.
- **`timeTracking`, `numberRange`, `week`, `timeline`** are missing from the storage table in `packages/core/service/AGENTS.md`. Recommendation: Shamsine documents their shapes there, then a later Minab phase can add types for them.
- **Minab gap: `JSON` has no key access.** `.location.lat` and `url.tab` (as `JSON`) cannot be read. Recommendation: Shamsine works with the guide's workaround now; a post-1.0 phase adds JSON path access (spec §5.6 says "once JSON path traversal exists").
- **Minab gap: the schema types are not exported.** `scalarType`, `ColumnType`, `ScalarType` are not in the root entry, so a host builds the type object by hand. Recommendation: a small phase (or a part of V1) exports them.
- **`languageVersion`** has no value or policy until Q5. The guide says to store the Minab package version meanwhile. Recommendation: keep it.
- **Soft deletes.** I could not tell if Dynodb rows with `deleted_at` set are filtered. Recommendation: check the data service before M.7.
- **Translations.** The fa, ar and tr text needs a native-speaker review (the `locales-translator` agent in the monorepo). Recommendation: review before it goes into `translations.json`.
