## Done

Hosts can now store a language version with each program, and a test shows which stored programs would change. All of "Done when" is met: corpus 0.2.0 exists and passes, the snapshot script works, and the docs page exists.

- `src/runtime/migrate.ts` (new): `LANGUAGE_VERSION` (1), `MIGRATIONS` (empty), `migrate(source, from, to)`. Exported from `src/runtime/index.ts`.
- `prepare(source, { languageVersion })`: newer gives `compat.newerLanguage`; older runs the migrations, and a missing step gives `compat.noMigration`; missing means the current version. A value that is not a whole number of 1 or more throws a `TypeError` (a bad call).
- Two new codes in the registry: `compat.newerLanguage` and `compat.noMigration`. The areas `compat` and `deprecated` are in the registry rules and in `docs/reference/diagnostics.md` (regenerated). There is no `deprecated.*` code yet, as the card says only to document the rule.
- `test/compat/`: `corpus.ts` (shared code), `compat.test.ts`, `README.md`, `corpus/0.2.0/` (88 programs: 77 from the spec and showcase, 11 from `examples/`).
- `scripts/compat-snapshot.mjs` and `npm run compat:snapshot <version>`. It never overwrites a folder.
- `docs/compatibility.md` (new, linked from `docs/README.md`). `changes/Q5.md`.
