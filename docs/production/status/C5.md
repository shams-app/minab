# C5 `CITEXT` and `LIKE`

Status: done
Date: 2026-10-03
Branch / PR: sema/awesome-meitner-06gi31

## Done
`TEXT` and `CITEXT` are now one text family (D15). They compare without a `CAST`, and the comparison ignores case when either side is `CITEXT`. `LIKE` now follows Postgres in the interpreter.

- **Checker.** New `comparableTypes` in `src/language/minab-types.ts`. `==`, `!=`, `<`…, `IN` (list and subquery) and the mix of `TEXT` and `CITEXT` pass. `baseTypesEqual` is unchanged, so `IF`/`CASE` branches and call arguments stay strict.
- **Interpreter.** Equality, ordering, `IN` and `LIKE` ignore case when either side is `CITEXT`. The test uses the inferred type, so it also works for literals, parameters and expressions, not only columns.
- **`LIKE`.** The regular expression is replaced by a copy of the Postgres matcher (`MatchText`). `%`, `_` and `\` agree. A pattern that ends with `\` fails only when the matcher reaches the `\`, as in Postgres (`"Hello" LIKE "Hello\\"` is `false`; `"Hello!"` fails).
- **SQL compiler.** When one side is `CITEXT` and the other `TEXT`, the text side is wrapped in `CAST(… AS citext)` for comparisons, `IN` (value and list items) and `LIKE`.
- **Spec.** §5.5 (the families are not "different types") and §7.2 (new paragraphs "Text family" and "`LIKE`"). The spec had no "known limitation" wording for `CITEXT`.
- **Tests.** `test/differential/cases/c5-citext-like.cases.ts` (52 cases, both runtimes). Four checker tests in `test/typechecking.test.ts`. The three `knownGap: 'C5'` cases are removed. `harness.test.ts` used a `C5` gap as its sample; it now uses a null-arithmetic gap.
