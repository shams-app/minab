# C3 `CAST` runs in the interpreter

Status: done
Date: 2026-10-03
Branch / PR: sema/ecstatic-allen-36cvkv

## Done
`CAST` now converts values in the interpreter by the rules of decision D16, and the compiled SQL agrees. A value that cannot convert fails with the new error `eval.castFailed` (params `value`, `from`, `to`).

- **`src/language/casts.ts` (new).** `castValue`: one rule for each pair of types (spec §5.5). Decimals are exact (`big.js`, from C2). Dates are text in the Postgres form (`2026-10-02`, `08:30:00`, `2026-10-02 08:30:00`).
- **Interpreter.** The `CastExpr` branch calls `castValue` with the static type of the operand (it tells a `JSON` string from a `TEXT` value).
- **SQL compiler.** `DECIMAL` to `TEXT`/`CITEXT` is `CAST(trim_scale(x) AS text)`. The compiler now gets the type checker for this.
- **Error code.** `eval.castFailed` in the registry; docs page regenerated.
- **Spec §5.5.** The "truncates or rounds" sentence is replaced by a table of every rule.
- **Tests.** `test/differential/cases/c3-cast.cases.ts` (about 90 cases, both runtimes). `test/casts.test.ts` (interpreter-only cases: error code and params, host `Date`, JSON, arrays). The three `knownGap: 'C3'` cases are removed. `test/support/minab.ts` has a new error kind `cast-failed` (our error and the Postgres errors `22P02`, `22003` count as the same failure).

Differences from the card, noted here:
- **No `INTEGER` to `BOOLEAN`.** Postgres refuses `bigint` to `boolean`, so the interpreter fails it too. `BOOLEAN` to `INTEGER` works (`1`/`0`), as in Postgres.
- **`JSON` to `TEXT` fails** in the interpreter, while Postgres succeeds (it prints the JSON text with its own spacing and key order). The card allowed `JSON` casts beyond "JSON text to JSON" to move to Later. Spec §5.5 says so.
- **Range of `INTEGER`.** The interpreter checks the JavaScript safe range (C2); the SQL type is `integer` (32 bits). A value between the two ranges differs. This is the C2 difference, not new.
- **Postgres accepts more text** (`"tomorrow"` as `DATE`, a `UUID` without hyphens, 7 or more fraction digits rounded). The interpreter follows the card: only the forms in the spec table. The spec says not to rely on the extra forms.
