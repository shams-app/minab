# C1 Differential test harness

Status: done
Date: 2026-10-02
Branch / PR: sema/clever-tesla-gh0ipn

## Done
Two test harnesses now run in every `npm test`, on PGlite (Postgres in the test process). The scalar harness runs one Minab expression in the interpreter and as SQL, and fails when the answers differ. The query harness runs whole programs and checks the rows and that `check` is clean. Each phase adds its own case file, so no shared file changes.

- **Dependency.** `@electric-sql/pglite` `^0.5.8` is a root dev dependency (same as the playground, approved in D09). `package-lock.json` and `bun.lock` are updated.
- **DDL moved.** `playground/src/engine/ddl.ts` is now `src/host/ddl.ts`. The old path is a one-line re-export. Only its `Row` and schema imports changed. `playground/test/ddl.test.ts` is unchanged and green.
- **Test database.** `test/support/database.ts`: `openTestDatabase()` gives `exec`, `query`, `executor`, `isolated`, `close`. It uses PGlite, or real Postgres when `MINAB_TEST_DATABASE_URL` is set. It loads `citext` and pins UTC. Each case runs in its own schema, which is dropped after. `numeric` returns as a `Decimal` (exact text), `bigint` as a number, dates as text, on both back ends.
- **Scalar harness.** `test/differential/` (`harness.ts`, `differential.test.ts` with `import.meta.glob`, `harness.test.ts`, `README.md`, `cases/`). Case shape as on the card. Errors agree when they mean the same (for example division by zero). A `knownGap` case must differ; if it agrees, the test fails with "gap fixed? remove knownGap". A record may name only some columns; the rest get neutral values.
- **Query harness.** `test/queries/` (`harness.ts`, `queries.test.ts`, `README.md`, `cases/`).
- **First cases** (`c1-` prefix): arithmetic, comparisons, logic, `IN`, `LIKE`, text, null rules, and 13 known gaps. Query cases: filter, project and order, filter through a ref, group by a relation, aggregate over a relation, `EXISTS`, `NOT EXISTS`, `LEFTJOIN`.
- `src/host/README.md`, `test/support/README.md` are new.

Differences from the card, noted here:
- **No changelog fragment.** Only tests and an invisible file move changed.
- **Literals alone are not used in scalar cases.** The compiler binds `1 + 2` as `$1 + $2` and Postgres refuses it ("operator is not unique: unknown + unknown"). The cases use columns. See Later.
- **The CITEXT gap** (the card says it may be a check error): `.ci == "hello"` already agrees (the parameter takes the column type). The gaps are `CITEXT` column against `TEXT` column (both sides) and `CITEXT IN [...]`. All three are marked C5.
- **Shared `ITEM_SCHEMA`** in `harness.ts`: building the language services takes about 3 seconds per distinct schema, so the case files share one.
- **Extra gap cases found while writing the first cases** (not on the card), marked `X1` or `none yet`: see Later.

## Later
- Literal-only expressions (`1 + 2`, `"a" + "b"`) fail in Postgres because the compiler binds literals untyped — wrong for hosts too, not only tests — none of C2–C8 names it — next card (or add typed parameters to C2/C4).
- `x IN [1, 2]` on a `null` `x`: the interpreter says `false`, SQL says `null`. Spec §7.7 says `IN` is repeated `==`. Known gap `none yet` in `c1-known-gaps.cases.ts` — C4 or next card.
- `x IN [1, null]` on a `null` `x`: interpreter `true`, SQL `null`. Same gap, same file — same card.
- `null + 1`: the interpreter fails ("expected a number"), SQL answers `null`. Spec does not say. Known gap `none yet` — C4 (it owns operators) after an owner decision.
- `is null` has no SQL form: known gap marked `X1` (the card that adds it).
- Run the suites against a real Postgres (see Checks) — needs a server — Q1.
