## Done
The language server now finds the right `minab.config.json` for each document. It reads a changed config without a restart. It offers completion, hover, go to definition and signature help from `src/editor/`. A new test drives the built server over stdio.

- `src/lsp/` (new, with a README): `startMinabLanguageServer({ connection? })`, `ConfigRegistry` (nearest config for a document, loaded once, services from the runtime `ServiceCache`, so equal schemas share one set), and `adapters.ts` (editor results to LSP types).
- Per document: the server walks up from the document's folder, like the CLI. No config, or a config that cannot be read, gives an empty schema. A config that cannot be read also shows one warning message.
- Watching: the server registers `workspace/didChangeWatchedFiles` for `**/minab.config.json`. On a change it forgets that config and checks all open documents again. The VS Code client handles dynamic registration itself, so `vscode-extension/src/extension.ts` is not changed.
- Features: completion (triggers `.`, `#`, `(`), hover, definition, signature help (triggers `(`, `,`).
- `src/language/main.ts` calls `startMinabLanguageServer`. `src/language/server.ts` (the `./lsp` package entry) re-exports it and keeps `startMinabServer`.
- Checks use the same options as the CLI (a syntax error stops the check).
- `test/lsp-stdio.test.ts` (9 tests): spawns `out/src/language/main.js --stdio` with a working directory that has no config. Two folders with different configs give different diagnostics. Completion after `.` gives the columns of the right schema and the right replace range. Hover, signature help, a changed config updates its document only, a document moved between folders uses the new config on reopen, and `shutdown`/`exit`.
