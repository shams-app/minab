## Later
- The first-ever `prepare` in a process builds the parser (about 95 ms). A host can call `prepare` once at startup. A `warmUp()` helper on the runtime would do it for them — lane R.
- The shared parser keeps the first service set alive (it holds that set's services). It is one set per process, so it is small — lane R if it ever matters.
- Completion parses the whole file on each call. Caching the parse by source hash would make it faster — lane E.
- The memory row measures the whole process (about 75 MB is Node and the loaded code). A row for Minab's own share needs a baseline — lane Q.
